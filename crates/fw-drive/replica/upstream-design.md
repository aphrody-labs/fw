## 3. Spacedrive (Apache-2.0, Rust core)

Layout of the tree (JSON `spacedrive.crates` lists the 25 crates): `core/` (`sd-core`: `src/domain`, `src/ops`, `src/infra`, `src/service`, `src/volume`), `crates/*` (store, task-system, fs-watcher, pvcache, bake, images, ffmpeg, media-metadata, sidecar-path, archive, actors, sdk, supervisor), `apps/{cli,server,tauri,native,mobile,web}`, `packages/{interface,ts-client,assets}`. The old `entry`/`location` tables are gone: durable state is a record table plus overlays (`AGENTS.md`, `PROJECT_STATUS.md`, `docs/core/design/source-durability.md`).

### Architecture points worth reusing in a Rust file service

| Point | What it is | Where |
| --- | --- | --- |
| Source = origin + ingest + store | one record shape for filesystems and adapters; generation data is rebuildable, assertions (tags, notes, policy) never are | `docs/core/data-model.mdx:61,134`; `crates/store/src/record.rs:1` (record table), `:10` (`record_overlay` with no FK, rebind evidence `(type, external_id, content_uuid)`, `hlc` and `device_uuid`) |
| Identity is not the path | stable record UUID, parent as an edge, path as a projection | `docs/core/data-model.mdx` Record, Hierarchy |
| Content identity in three strengths | Unknown (metadata), Candidate (sampled blake3), Confirmed (full-byte integrity hash); only Confirmed authorises dedup or deletion. Files up to `MINIMUM_FILE_SIZE` = 1024*100 are hashed whole; larger files take `SAMPLE_COUNT` = 4 samples of `SAMPLE_SIZE` = 10 KiB plus 8 KiB header and footer. Note: there is no `cas_id` in this version; it was replaced by `content_hash` and `generate_integrity_hash` | `core/src/domain/content_identity.rs:109,112,113,114` (consts), `:125` (`generate_content_hash`), `:143` (`generate_integrity_hash`); `docs/core/data-model.mdx:122-124` (section at 115) |
| Indexer as a job | `IndexerJob` with a discovery phase, then content identification as separate work; claimed batches are flushed before the next claim | `core/src/ops/indexing/job.rs:151`, `core/src/ops/indexing/phases/mod.rs:8`, `docs/core/indexing.mdx:89` |
| Watchers feed the same model | `sd-fs-watcher`, platform-agnostic, normalised events, coalesced before expensive work, never a replacement for a full walk | `crates/fs-watcher/src/lib.rs:1`, `docs/core/indexing.mdx:153` |
| Job contract | typed input/output, dedup by kind plus stable key, checkpoints, progress units, resumable; dispatch writes the row before running | `core/src/infra/job/traits.rs:14` (`Job`), `:40` (`JobHandler`), `docs/core/jobs.mdx:46`; `crates/task-system/src/lib.rs:4` |
| Thumbnails | hot tier is a memory-mapped tile cache (`thumbs.pvcache`, BGRA8, record uuid keys, one writer, many read-only mappers); `sd-bake` is a cost-ordered chain of producers that yield a tile or a typed decline; generation submits 32 files per batch at lower priority than viewport requests; cache validity = size, mtime, recipe revision, FFmpeg availability | `crates/pvcache/src/lib.rs:1`, `crates/bake/src/lib.rs:9`, `docs/core/thumbnail-generation.mdx:39,52` |
| Tags as assertions | a tag definition (stable UUID, path such as `Work/Clients/Acme`, colour, icon) is separate from an application (append-only assertion with record UUID, path as rebind evidence, convergent content UUID, apply/remove flag, HLC, device); the latest HLC wins, device UUID breaks ties | `docs/core/tagging.mdx:16,21,44` |
