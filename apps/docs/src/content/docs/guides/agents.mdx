An agent works best when it can read the rules of a project and call its tools. fw gives it three things: instruction files, an MCP server and skills.

## Instruction files

Put an `AGENTS.md` at the root of the repository. It holds the rules an agent must follow: how to build, how to test, what not to touch. Claude Code reads `CLAUDE.md`; keep it as a short pointer to `AGENTS.md`.

Run `fw onboard [dir] | fw onboard export <all|mcp|opencode|zed> [--dir <dir>]`. It describes the workspace for agents and can export configs for MCP, OpenCode and Zed.

```bash
fw onboard export all
```

## Plain-text docs

This site serves text for machines:

- [llms.txt](/llms.txt) lists every page with a one-line note.
- [llms-full.txt](/llms-full.txt) holds every page in one file.
- Add `index.md` to any page address for the markdown source, for example `/cli/index.md`.

## MCP

`fw mcp | fw mcp <list|add|remove>` serves fw tools over stdio, and `fw serve` serves them over HTTP on `/mcp`. The server lists 17 tools. Each has a page with its input schema: see the [MCP tools](/mcp/).

## Skills

Skills are folders with a `SKILL.md`. The command is `fw skills <list|read|install>`.

```bash
fw skills list
fw skills read <name>
```

## Check your setup

1. Run `fw onboard export mcp` in your project.
2. Open the `.mcp.json` it wrote.
3. Start your agent and ask it to call `fw_status`.
