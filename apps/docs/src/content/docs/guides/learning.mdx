fw learns locally. It reads your git history, a code graph and your docs, stores them in SQLite, and searches them without a network call.

## Commands

| Command | Usage |
|---|---|
| `fw learn` | fw learn &lt;status\|harvest\|distill\|search\|loop\|systemd&gt; [--xfs-root &lt;dir&gt;] |
| `fw corpus` | fw corpus &lt;sources\|status\|sync\|search\|read\|systemd&gt; [--root &lt;dir&gt;] |
| `fw mem` | fw mem &lt;add\|search\|timeline\|get\|list\|stats\|prune&gt; |
| `fw graph` | fw graph &lt;build &lt;dir&gt; [--json f] [--report f]\|query &lt;question&gt;\|explain &lt;node&gt;\|path &lt;a&gt; &lt;b&gt;\|report\|export&gt; |
| `fw docs` | fw docs &lt;resolve\|query\|ingest\|list&gt; [lib] [topic] [--tokens 4000] |

The table is read from `fw <command> --help`.

## Learn from a repository

1. Go to the repository.
2. Harvest history, graph and docs.

```bash
fw learn harvest
```

3. Look at what was stored.

```bash
fw learn status
```

4. Search it.

```bash
fw learn search "how are releases published"
```

## Run it on a server

`fw learn systemd` prints a systemd unit for a VPS. `fw learn loop` repeats harvest and distill.

## Reference docs

`fw corpus` keeps a polite, resumable copy of design, Android, Chromium, Rust and Cargo docs. `fw learn search` includes it. See the [`fw corpus`](/cli/corpus/) and [`fw learn`](/cli/learn/) pages.
