# fw agent contract

- **First contact**: run `fw onboard`, or read `MAP.tsv`, `LIFETIMES_AND_STYLE.md` and `.agents/workflows/fw-agent-journey.md`. Any ACP, MCP or CLI agent can use `fw` the same way.
- **Principle: everything is a file, code is a design material** ([Unix](https://en.wikipedia.org/wiki/Everything_is_a_file), [Google Design](https://design.google/library/code-is-a-design-material)): every capability takes files or stdin and writes files or stdout, so tools compose by path and pipe (`fw convert`, `fw-video`, `fw-m3 css`). Design artifacts are generated code that round-trips and is tested against drift (colors from `product.toml` [brand] through `fw-m3`, video to SVG/Markdown/HTML/JSX/GPUI through `fw-video`), never a hand-copied value.
- **Search hygiene**: `.rgignore` and `.fdignore` hide `target/`, `dist/`, `uv.lock` and other generated trees.
- **Workspace**: `Cargo.toml` members are `crates/fw-*` and `xtask` (`cargo metadata --no-deps --format-version 1`; tiers and gates in `MAP.tsv`). `os/*`, `native/*` and `packages` are not workspace members (`exclude` in `Cargo.toml`). Builds use `x86-64-v3` and `mimalloc`; Clippy runs with `-D warnings`; tests are never skipped or deleted.
- **Binary (`fw`)**: `fw --help` is the command list and `fw <command> --help` the usage; `README.md` groups them. `fw align`, `fw train`, `fw heretic`, `fw abliterate` (except `plan`) and `fw infer --gguf` run reference math on synthetic data, not on model weights.
- **Gate**: `cargo xtask ci [fast|all]` runs clippy, `cargo test --workspace`, `uvx ruff check .`, `bun run test:ci`, then (`all` only) the `native/fw-abi` tests, the `fw-wasm` wasm32 build and the Cloudflare dry run, plus the purity and `MAP.tsv` checks. Heavy runs go to `fr1` through `bun tools/fr1.ts gate -p <crate>` (or `run -- <command>`): commit first, git is the only transport, one checkout per repository per machine (`~/src/<repo>` on fr1, one shared `target`, sccache); no tar copies, no scratch clones.
- **Git**: commit explicit file paths on `main` and check `git diff --cached --name-only` first (other agents stage in the same checkout); bring a shared checkout up to date with `bun tools/sync-tree.ts` (merges upstream without losing local work, then pushes); never `git stash`, `git reset --hard` or `--amend` after a push; no AI attribution trailers; the repository is private (`aphrody-labs/fw`).
- **NT/Windows forks**: owned by `fw-nt` (`fw-nt/forks.toml`, synced by `fw-nt/tools/sync.ts`); `upstreams.toml` here lists none of them.
- **Dependency direction**: repositories are sibling checkouts under one root. The stack order is 1 `fw`, 2 `aphrody`, 3 `ay`, 4 `nie`, 5 `shenron`, then satellites. A Rust dependency between repositories may only point down the stack (to `fw` from everyone), never up and never in a cycle, so `fw` builds from its own checkout alone.
