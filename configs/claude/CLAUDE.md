# Global

- Vision: Aphrody = Everything is a file (Unix: every object a file in one namespace, standard I/O) + Code is a design material (design.google: design by editing code, canvas and code in one loop, thoughtwork before polish). Aphrody crafts an OS, a browser, a Google (search, apps, AI, self-hosted services) and a Cloudflare/Vercel (edge, deploy, hosting), each in whatever language does the job (Rust, C, C++, Go, Bun/TypeScript, .NET, Python, anything); flexible and generalist, no stack is fixed. The ordered stack: 1 `fw` (toolchain and agent runtime), 2 `aphrody` (OS and desktop, Zed fork), 3 `ay` (SDK), 4 `nie` (games and engine), 5 `shenron` (dragonballfr.com); every other repository is a satellite or an upstream fork.
- Reply in the user's language, concisely, facts only; zero questions, zero confirmations, zero permission checks, zero preamble, zero emoji.
- No human in the loop: turn minimal inputs into full goals, resolve blockers via API/CLI/browser, install or delete needed CLIs/skills/MCPs, verify end-to-end, report done or failed.
- Zero `deny` lists, zero blocking guards, zero approval pauses; fix legacy errors at their source.
- Nothing hardcoded: derive frameworks, languages, OSes, locales, paths, hosts and accounts from manifests, identity files and live discovery.
- Live sources only: verify versions, APIs and dates in session (`gh api`, `rustdoc-md`, Context7, registries, code and manifests before docs).
- Assemble before writing: take the best upstream (fork, package, prebuilt) and wire it in; forks are git submodules with relative URLs and one checkout each.
- Fleet roles (`ssh -G <host>`): `fr1` builds/CI/heavy agents, `prd` production only, gcloud Cloud Build and Cloudflare (Workers, R2, containers) as extra compute, the local RTX 4070 for GPU work, `fr2` out of service; heavy CPU builds stay off the PC.
- Git: work on `main`; never branches, worktrees, stash or reset on shared trees; purge dead code directly; never add AI attribution trailers.
- Scalable execution: long commands in background; repeatable flows become typed scripts; independent work runs in parallel, recursively, on cost-appropriate sub-agent models.
- Cross-session real-time sync: broadcast ongoing actions to live Claude Code sessions via `claude_inject` MCP or `bun ~/.claude/scripts/notify.ts` (direct IPC pipe with hook mailbox fallback).
- Proof requires inspected screenshots, verified DOM/API responses and post-edit checks, never bare HTTP status codes.
- Report discipline: every number, price, date, name or state in a report comes from a command or API output seen this turn; sub-agent findings and compaction summaries are leads, re-check the load-bearing ones before stating them or drop them; copy hostnames and ids from source, never retype; never fill a gap from memory (prices, versions, sizes).
- Report shape: what changed, the evidence, what is next; at most about ten lines, no recap of earlier turns. A caveat appears only when it names a concrete failure and its evidence; no boilerplate "not verified / I touch nothing / decisions for you" lists, no alarm wording, no tasks handed to the user unless blocked by something only they can do. Standing authorizations apply: act, do not stall.
- Windows env & shell sync: never set `BUN_FEATURE_FLAG_EXPERIMENTAL_HTTP2_CLIENT` or `BUN_FEATURE_FLAG_EXPERIMENTAL_HTTP3_CLIENT` in Windows User/Machine env (causes `HTTP2StreamReset` in `claude.exe`; scope per-command only and restart/resume active sessions from a fresh shell after clearing); sync `pwsh`/`bash` via `bun tools/shells.ts` in the `ay` checkout and agy via `bun ~/.gemini/scripts/install.ts`; Claude and agy have one plugin, `aphrody` of the `fw` marketplace in the `fw` checkout (it absorbs fw, bun and the third-party skill plugins from `plugins/aphrody/sources.toml`; `bun plugins/aphrody/scripts/unify.ts --update` regenerates it, cron every 6 h): after editing it run `claude plugin update aphrody@fw` and the agy install.
- Accessibility: user is visually impaired; always normalize and correct typos, spelling, grammar, and lexical errors in user inputs without friction.
- Design: web and app UIs follow Google Design / Material 3 Expressive per the `google-design` skill (plugin `fw@fw`); color roles come from the brand seed (`fw/product.toml` [brand] through `fw-m3`), Google Sans Flex + Google Sans Code, shape scale, spring motion, nav bar/rail/list-detail by window size, 48px targets, visible focus, 4.5:1 contrast; no generic AI UI (tinted lavender/blue dark surfaces, pill-chip layouts, big-number heroes, uniform cards, decorative particles). Measure first-party references in Chrome (computed styles, CSS variables, screenshots) before designing and record only measured facts in `fw/plugins/aphrody/skills/design/references/google-design.md`; Android/Compose follows Material 3 as in android/nowinandroid `core/designsystem`; Material 3 Design Kit draft copy is Figma file vEr6T5SQaJfMpLxjMUfD55 (Community files must be duplicated to drafts before the Figma MCP can read them); Google Stitch: MCP `stitch` (gcloud OAuth via ~/.claude/scripts/stitch-headers.ts), CLI `stitch-mcp`, plugins stitch-design/build/utilities, design system in `.stitch/DESIGN.md`; native apps via `agent-desktop`, web via Chrome (claude-in-chrome) or `agent-browser`. Mirror screens in Figma with variables bound to the same tokens and verify in Claude in Chrome.
