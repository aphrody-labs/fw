---
name: fleet
description: "Run a command, schedule builds, deploy or check on the fleet (fr1 heavy builds, prd production), gcloud Cloud Build. Use for any remote ssh/scp/systemctl/build; never a heavy build on the PC CPU."
---
> Cloudflare compute and the local RTX 4070; fr2 is out of service.


1. Always check live capacity and peer locks first: inspect `fleet_status` (or `bun run fleet:lb probe --all`) and `relay` `session_list` / `session_inbox` before writing under the shared build dir (`<work>` of the host) or launching heavy Cargo/C++ builds on `fr1`.
2. Launch every long remote command (builds, installs, syncs, benchmarks, kernel compiles) directly inside a detached `tmux` session via `bun "$HOME/.gemini/scripts/tmux-run.ts" start <host> <job> "<cmd>"` and inspect non-blockingly with `status <host> <job>`. For short one-liners, pipe single-quoted heredocs through `@' ... '@ | ssh <host> "tr -d '\r' | bash"`.
3. Exit 255 / slow host: `@' ... '@ | ssh <fr1> "tr -d '\r' | bash"` checking `uptime` (and clearing stale processes only when owned by your task/session).
4. Deploy a file: `scp -q <src> <host>:<work>/X/` after ensuring `<work>/X` ownership via heredoc (`<work>` from `assets/os/fleet_cluster.toml` or `ay.toml`).
5. Service: `ssh prd "sudo systemctl restart <svc> && systemctl is-active <svc>"`.
6. Prove a deploy with content, not a status: rendered page or real API response payload check; bare HTTP 200 proves nothing.
7. Never break prod: verify on build/test host before `prd`. Detailed roles: memory fleet-roles.md.
8. Compute targets, in order of use: `fr1` (12c/47G primary, `nativelink`/`sccache-dist` scheduler) for heavy builds, CI and agents; `prd` (8c AMD EPYC 9354P/32G) production plus build bursts isolated in a systemd slice (`Nice=19`, `IOSchedulingClass=idle`, `CPUWeight=15`, `MemoryHigh=12G`); gcloud Cloud Build (`gcloud builds submit`) for builds that exceed `fr1`; Cloudflare Workers, R2 and containers for edge compute and artifacts; the local RTX 4070 for GPU work (CUDA, wgpu, model inference). Build with `RUSTC_WRAPPER=sccache`, `mold` (release/LTO) or `wild` (dev/test), `CARGO_INCREMENTAL=0`.
9. `fr2` (6c/11.7G worker, NFSv4.2 `nconnect=8`) is out of service: unreachable, assign nothing to it, skip it in `fleet_status`; tests, bench and research go to `fr1`, gcloud or Cloudflare until it returns. Anything that lived on its NFS `<work>/shared` or its services (SearXNG, credentials) is unavailable meanwhile.
10. Canonical build layout on fr1 (`ay.toml [paths.build].work` = `/srv/xbuild`, XFS on LVM `xbuild` over sdb+sdc, 805G; the root sda is ext4 and must stay under 70%): one checkout per repo at `$WORK/src/<repo>` (`~/src` is a symlink to it), shared `CARGO_TARGET_DIR=$WORK/target/<repo>` chosen by the cargo shim `$WORK/bin/shims/cargo` (first in PATH, from the git toplevel name; an explicit `CARGO_TARGET_DIR` wins), `SCCACHE_DIR=$WORK/cache/sccache`, `TMPDIR=$WORK/tmp` (set in `/etc/environment` and `/etc/profile.d/aphrody-work.sh`). Agents work in place on main with disjoint paths; no per-agent clones, no `~/ci`, `~/build`, `~/wb`. Benchmarks use a `git clone --shared` under `$WORK/bench`, removed after.
11. Build cluster as code: `cluster/build.toml` is the single source of hosts, mesh addresses, ports and paths; `bun configs/claude/scripts/build-cluster.ts plan|apply|status` renders and installs the sccache-dist scheduler (fr1) and servers (fr1, prd; prd inside `fairwind-build-worker.slice`: CPUWeight 15, MemoryHigh 12G, Nice 19, idle IO). NativeLink: scheduler and worker on fr1 (`/etc/nativelink/*.json5`), worker on prd (same config, `NL_JOBS=8`, same slice). Shared Rust cache: R2 bucket `aphrody-sccache` through `/srv/xbuild/sccache-r2.env` (fr1) and `/srv/build/sccache-r2.env` (prd), mode 600, `SCCACHE_BUCKET`, `SCCACHE_ENDPOINT`, `SCCACHE_REGION=auto`.
12. fr1 and prd differ in ISA: prd runs Arch/CachyOS packages built for x86-64-v4 (Zen 4, `sccache-dist` from pacman crashes with SIGILL on fr1); fr1 is Haswell (x86-64-v3, no AVX-512). Never copy a binary from prd to fr1; build it on fr1 with `RUSTFLAGS="-C target-cpu=x86-64-v3"` (sccache-dist: `cargo install sccache --version 0.19.0 --locked --features "dist-client dist-server vendored-openssl"`).
13. prd builds: user `builduser`, `RUSTUP_HOME=/srv/build/rustup CARGO_HOME=/srv/build/cargo`, checkout `/srv/build/src/<repo>` (git clone, never NFS: the NFS export is `<work>/shared` only), targets `/srv/build/target` on the btrfs subvolume `/srv/build` (zstd:1), run through `systemd-run --slice=fairwind-build-worker.slice -p Nice=19 -p IOSchedulingClass=idle`.
14. Measured limits of the cluster (2026-11-21, fw-bin release, thin LTO): sccache-dist distributes compiles to both servers (`sccache --dist-status` shows 2 servers, 20 CPUs) but `libc 0.2.191` fails in the sandbox (`bits/../../x86/...` path through an empty directory), so cargo builds of fw cannot use it until libc or sccache changes; R2-backed sccache hits across hosts only for crates whose absolute paths match (30 of 99 hits with `CARGO_HOME` and target dir under the same `/srv/cb` path on both hosts, 0 with different paths); workspace crates still differ because cargo resolves the checkout to its real path (`/srv/build` on prd, `/srv/xbuild` on fr1).
