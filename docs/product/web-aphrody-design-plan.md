## Brand conflict found

fw `product.toml` [brand] says seed `#e2dbad`, `tonal-spot`. aphrody `product.toml` says `#135B82`, `expressive`.

The site uses the aphrody identity, but the stack needs one declared source of brand per product and a rule for how the family relates; it is recorded as a fix for the hardcode lot. Every colour below is an M3 role generated by fw-m3 from `#135B82`/`expressive`. No hex is typed into CSS.

## Subject, audience, job

- **Subject:** Aphrody, a local-first desktop OS whose shell, compositor and editor are GPUI, and which runs Zed extensions.
- **Audience:** developers and power users choosing an OS or desktop, and Zed users.
- **Job of the page:** show the real desktop working, then get the visitor to install it (releases.aphrody.com manifest) or try it in the browser.

## Pass 1: token plan

- **Color:** M3 expressive roles from seed `#135B82`, a deep teal-blue:
  - `surface` and `surface-container-*` for the page;
  - `primary` for the single install action;
  - `tertiary` for the live-desktop frame accent only;
  - light and dark schemes both generated; contrast 4.5:1 checked per pair by fw-m3.
- **Type:**
  - Google Sans Flex for everything. The display uses the variable width and optical-size axes, wide and heavy for the one headline line, regular for body.
  - Google Sans Code only where the page shows real commands (install, `fw` CLI).
  - Scale: M3 type scale. Body 16 px, line length under 72 characters.
- **Layout:**

```
[ header: Aphrody | Desktop  Studio  Toolchain  Docs | Install ]
[ HERO: the live desktop itself, a real GPUI/wasm session in a frame sized to the viewport,
  started after first paint in a worker; before it boots, a real screenshot of the same frame;
  under it, one line: what Aphrody is (from product.toml), and the install action for the
  visitor's OS (from the release manifest) ]
[ Desktop: shell, compositor, windows (a real recorded clip from media.aphrody.com, AV1 ladder) ]
[ Studio: the Zed-compatible editor, with the extensions count read from the code ]
[ Toolchain: fw, real CLI commands with their real output ]
[ Release train: channels canary to lts with live versions from releases.aphrody.com ]
[ footer: docs.aphrody.com, GitHub aphrody-labs/fw, licence ]
```

  Left-aligned text on a 12-column grid. On mobile, the hero becomes the screenshot plus a "Try in browser" action; the live session only starts on demand there.
- **Principles:**
  1. The product is the hero; no illustration stands in for it.
  2. Every number and version on the page is read live or generated from code at build time.
  3. One bold thing, the live desktop frame; everything else is quiet.
  4. Motion only answers the user. The single orchestrated moment is the desktop booting in the frame.

## Pass 2: review against the brief and the generated-page tells

| Item | Generic default? | Change |
|---|---|---|
| Hero | A big-number hero would be the default. | Already the product itself, kept. |
| Sections as identical rounded cards | Default SaaS kit. | Each section takes the shape of its content: a clip, an editor screenshot, a terminal transcript, a channel table. Radii follow the M3 shape scale by role, not one radius. |
| Eyebrow labels above headings | Template chrome. | Removed; headings say what the section is. |
| Arrows on buttons, middle-dot meta strings | Tells. | None. Buttons say the action ("Install for Windows", "Try in browser"). |
| Dark near-black with one accent | Common default. | Light and dark both come from the seed's tonal palette; no tinted near-black literal. |
| Fade-in on every section | Generic motion. | None. Only the boot moment and user-triggered transitions with M3 springs; reduced-motion gives the static screenshot. |
| Release table in monospace | Tell. | Google Sans Code only for real commands; versions in Sans Flex tabular numerals. |
