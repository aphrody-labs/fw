# Web stacks against pure Rust: parity matrix (2026-11-21)

Order of the owner, 2026-11-21: an audited parity and equivalence matrix between the web stacks we use or reference and their pure-Rust equivalents. Queue file: `docs/agents/queue/ui-stack-parity-matrix.md`. Full cells with every citation: `docs/research/web-vs-rust-parity-2026-11.tsv` (242 rows). Raw benchmark runs: `docs/research/web-vs-rust-parity-2026-11-bench.tsv`.

## Method

- **Rows** come from each stack's own artefacts at today's version: the npm tarball file lists (`@base-ui/react@1.9.0`, `@mui/material@9.5.0`, `better-auth@1.7.27` and `@better-auth/core`, `elysia@1.4.32`, `next@16.4.6`, `three@0.187.0`, `motion@14.14.0`), the `ui.shadcn.com/r/index.json` registry (65 `registry:ui` items) and the official Elysia plugin repositories (`gh api orgs/elysiajs/repos`). MUI rows are the top-level components of the tarball; sub-parts (`AccordionSummary`, `ListItemText`, `TableRow` and similar) fold into their parent.
- **Ours** is the fw monorepo at `6fae51745583a6742144a47fd1b80079b4934c5d` (`fw@6fae51745 path:line`). **Best Rust equivalent** is the best-covered upstream; cites read `owner/repo@commit path:line` at the HEAD read on 2026-11-21 (longbridge/gpui-kit `4373234ff46df3a3227972788a41dc6603d352ce`, DioxusLabs/dioxus-components `9a758255ea26e2b20c8cecf4c1c946feb9e71da7`, rust-ui/ui `4f5a516e76d75a15a587ab2169352cf34fd318d0`). Web cells cite `package@version path` inside the npm tarball.
- **Status rule.** `present`: a module or symbol with the same name exists. `partial`: the nearest module by name or alias exists and the text says which; behaviour was not diffed line by line. `missing`: no file or symbol found by name and by grep (the zero-hit greps are named in the reason). `n/a`: framework primitives (layout, click-away) that GPUI provides as part of the framework.
- **Decision** per row: adopt upstream, port, keep ours, or keep the web stack, each with its reason.
- Versions of the Rust candidates read from crates.io the same day: gpui-component 0.10.0, gpui 0.2.2, axum 0.8.9, actix-web 4.20.0, leptos 0.8.23, dioxus 0.7.10, bevy 0.20.1, wgpu 30.0.2, three-d 0.19.0, iced 0.14.0, egui 0.37.0, slint 1.19.0.

## Benchmarks

Conditions, stated because they bound what the numbers mean:

- **Host** prd (8 cores, Arch, rustc 1.100.0 from the system package, Bun 1.4.5-canary.1; `node` on prd is the same 153,250,240-byte binary as `bun`, so Next.js ran on Bun). Load average at run time 27 to 47 on 8 cores (other agents' jobs): latency and requests per second are inflated and noisy, so the comparison column is **CPU microseconds per request** (server utime plus stime from `/proc/<pid>/stat`, divided by successful responses), which does not depend on how long the request waited. Server pinned to cores 4 and 5, load generator `oha` (static binary, keep-alive, 32 connections) on cores 6 and 7, 3 runs of 6 s after a 2 s warm-up, median reported, raw runs in the bench TSV.
- **Builds** on fr1 (rustc 1.100.0, `--release`, `lto = "fat"`, `codegen-units = 1`, `panic = "abort"`, `strip`), wasm built with `opt-level = "z"`, then `wasm-bindgen 0.2.130` and `wasm-opt -Oz`. JS bundles built on the PC with `bun build --minify` (Bun 1.4.6-canary), NODE_ENV production.
- Sources: `/tmp` scratch projects, not committed (see the generator lot); each server answers the same routes (`/` text, `/json` object, `/ssr` a 100-row table).
