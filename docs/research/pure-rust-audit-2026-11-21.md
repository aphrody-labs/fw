## Architecture verdict

The stack is already mostly Rust: 3,022,544 Rust code lines in fw at `ec2d7a5e`. The debt is a second runtime layer: TypeScript on Bun that duplicates the Rust crates in tooling, agent runtime, edge Workers and scripts, plus a few platform glue layers.

Bun itself is a Rust runtime upstream now (88.6 MB of Rust, per the bun-upstream skill).

The goal is therefore one language for our own code. The port order follows the dependency direction:

1. tools and scripts;
2. Workers;
3. agent runtime;
4. UI surfaces;
5. platform glue.

## Train

Each item is one path-scoped batch with its gates green, executed by the monorepo and layout owner (crates-map) or a dedicated port agent:

1. **Prerequisite:** the monorepo merge and layout-2026 moves land first, so ports land at their final paths.
2. **For every area:**
   1. Write a characterization test of the TS/Python behavior: CLI output, HTTP responses, files written.
   2. Port it to Rust behind the same command or route.
   3. Run the same test against both.
   4. Switch the callers (workflows, hooks, docs).
   5. Delete the old code.
   6. Add a guard: a CI check that fails on new non-Rust source outside the Deliberate list.
3. **Order:** R13, R12, R5, R9, R15 (tooling the agents use every day), then R11, R10 (Workers), then R2, R3, R14 (runtime and packages), then R7, R8, R4 (UI and platform).

To re-derive a count before each batch, re-run the tokei commands above on the batch's base commit; quote deltas against that reading.
