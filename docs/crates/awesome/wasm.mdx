## About each crate

- **uuid**: A library to generate and parse UUIDs.
- **reqwest**: higher level HTTP client library
- **wasm-bindgen**: Easy support for interacting between JS and Rust. 
- **js-sys**: Bindings for all JS global objects and functions in all JS environments like Node.js and browsers, built on \`#\[wasm\_bindgen\]\` using the \`wasm-bindgen\` crate. 
- **whoami**: Rust library for getting information about the current user and environment
- **rhai**: Embedded scripting for Rust
- **wasmtime-wasi**: WASI implementation in Rust
- **nalgebra**: General-purpose linear algebra library with transformations and statically-sized or dynamically-sized matrices.
- **gloo-timers**: Convenience crate for working with JavaScript timers
- **burn**: Flexible and Comprehensive Deep Learning Framework in Rust
- **wasmi**: WebAssembly interpreter
- **wasmtime-environ**: Standalone environment support for WebAssembly code in Cranelift
- **candid**: Candid is an interface description language (IDL) for interacting with canisters running on the Internet Computer.
- **wasip3**: WASIp3 API bindings for Rust
- **gloo-net**: HTTP requests library for WASM Apps
- **wasip2**: WASIp2 API bindings for Rust
- **gloo-utils**: Convenience crate for common \`web\_sys\` features
- **wasmer**: High-performance WebAssembly runtime
- **wiggle**: Runtime components of wiggle code generator
- **pdfium-render**: A high-level idiomatic Rust wrapper around Pdfium, the C++ PDF library used by the Google Chromium project.
- **wasi-common**: WASI implementation in Rust
- **sqlite-wasm-rs**: \`wasm32-unknown-unknown\` bindings to the libsqlite3 library.
- **wasmer-types**: Wasmer Common Types
- **ehttp**: Minimal HTTP client for both native and WASM
- **jwt-simple**: JWT authentication with JSON Web Token signing and verification (JWS), encryption (JWE), and custom claims. Supports RSA, ECDSA, Ed25519, and ML-DSA.
