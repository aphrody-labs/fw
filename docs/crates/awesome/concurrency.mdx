## About each crate

- **parking\_lot**: More compact and efficient implementations of the standard synchronization primitives.
- **crossbeam-channel**: Multi-producer multi-consumer channels for message passing
- **pollster**: Synchronously block the thread until a future completes
- **tokio-tungstenite**: Tokio binding for Tungstenite, the Lightweight stream-based WebSocket implementation
- **rayon**: Simple work-stealing parallelism for Rust
- **crossbeam-utils**: Utilities for concurrent programming
- **portable-atomic**: Portable atomic types including support for 128-bit atomics, atomic float, etc. 
- **moka**: A fast and concurrent cache library inspired by Java Caffeine
- **crossbeam-queue**: Concurrent queues
- **async-lock**: Async synchronization primitives
- **crossbeam-epoch**: Epoch-based garbage collection
- **crossbeam**: Tools for concurrent programming
- **dashmap**: Blazing fast concurrent HashMap for Rust.
- **crossbeam-deque**: Concurrent work-stealing deque
- **scc**: A collection of high-performance asynchronous/concurrent containers with both asynchronous and synchronous interfaces
- **lock\_api**: Wrappers to create fully-featured Mutex and RwLock types. Compatible with no\_std.
- **loom**: Permutation testing for concurrent code
- **portable-atomic-util**: Synchronization primitives built with portable-atomic. 
- **async-tungstenite**: Async binding for Tungstenite, the Lightweight stream-based WebSocket implementation
- **rtrb**: A realtime-safe single-producer single-consumer ring buffer
- **event-listener**: Notify async tasks or threads
- **parking\_lot\_core**: An advanced API for creating custom synchronization primitives.
- **triomphe**: A fork of std::sync::Arc with some extra functionality and without weak references (originally servo\_arc)
- **blocking**: A thread pool for isolating blocking I/O in async programs
- **async-executor**: Async executor
