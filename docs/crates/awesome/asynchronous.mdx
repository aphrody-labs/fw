## About each crate

- **tokio**: An event-driven, non-blocking I/O platform for writing asynchronous I/O backed applications. 
- **tokio-util**: Additional utilities for working with Tokio. 
- **tonic**: A gRPC over HTTP/2 implementation focused on high performance, interoperability, and flexibility. 
- **futures**: An implementation of futures and streams featuring zero allocations, composability, and iterator-like interfaces. 
- **quick-xml**: High performance xml reader and writer
- **tower-http**: Tower middleware and utilities for HTTP clients and servers
- **async-trait**: Type erasure for async trait methods
- **tracing**: Application-level tracing for Rust. 
- **mio**: Lightweight non-blocking I/O.
- **tonic-build**: Codegen module of \`tonic\` gRPC implementation. 
- **opentelemetry**: OpenTelemetry API for Rust
- **tokio-rustls**: Asynchronous TLS/SSL streams for Tokio using Rustls.
- **actix-web**: Actix Web is a powerful, pragmatic, and extremely fast web framework for Rust
- **opentelemetry-otlp**: Exporter for the OpenTelemetry Collector
- **tracing-subscriber**: Utilities for implementing and composing \`tracing\` subscribers. 
- **tokio-stream**: Utilities to work with \`Stream\` and \`tokio\`. 
- **axum**: HTTP routing and request handling library that focuses on ergonomics and modularity
- **async-compression**: Adaptors between compression crates and Rust's modern asynchronous IO types. 
- **h2**: An HTTP/2 client and server
- **pollster**: Synchronously block the thread until a future completes
- **tracing-opentelemetry**: OpenTelemetry integration for tracing
- **bon**: Next-gen compile-time-checked builder generator, named function's arguments, and more!
- **tonic-prost**: Prost codec implementation for tonic
- **tokio-tungstenite**: Tokio binding for Tungstenite, the Lightweight stream-based WebSocket implementation
- **opentelemetry-semantic-conventions**: Semantic conventions for OpenTelemetry
