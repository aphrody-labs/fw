# media-cdn: media.aphrody.com, images, video ladder and sprites on R2 (live, follow-ups queued)

Spec: `docs/product/cahier-des-charges.md` R1 to R7, matrix rows 1, 2, 5, 6, 8, 25. Roadmap: M5 (done), M6 follow-ups. Reference: `plugins/aphrody/skills/design/references/google-design.md`, "Googlebook product page, measured".

## Goal
One media host for the monorepo: images in AVIF, WebP and a fallback with `=w`/`=s` variants, an AV1/VP9/H.264 video ladder at 600, 1024, 1440 and 1920 CSS px (1x and 2x), SVG sprites, immutable hashed URLs, produced by our own pipeline on the cluster. Fonts stay on `material.aphrody.com`.

## Done (verified 2026-11-21)
- Worker `media-cdn` (`cloudflare/media-cdn`, deployed version 3f82d7b0-027f-4a06-acc5-aa9059b75bae) with R2 `MEDIA` -> `aphrody-media` and Images `IMAGES`; hostname, record and bucket created by the estate (`cluster/estate.toml`, `edge-estate`). `GET https://media.aphrody.com/v1/` answers 200.
- Tools: `tools/media-cdn/{grammar,manifest,sprite,build,publish,verify,fixtures}.ts`; layout allow entries in `layout.toml`. `cd cloudflare/media-cdn && bun test`: 40 tests pass; `bun check -p .` clean.
- Fixtures built on `fr1` (`/srv/xbuild/media-cdn`, synthetic content generated by `fixtures.ts`): 2 videos (3840x2160 and 2400x2400), 4 images (2 sources and 2 posters), 1 sprite of 308 symbols; published: 194 plus 193 objects, 16,743,915 B in the second upload.
- `bun tools/media-cdn/verify.ts` against the live host: 987 checks passed, 0 failed (141 image rungs, 3,744,303 B; 42 video rungs, 8,307,645 B; manifest revision 5db691d0). It checks per rung: status, Content-Type, Content-Length equal to the manifest, magic bytes, `immutable`, plus negotiation, `Vary: Accept`, no upscaling, 304, ranges (206 with the exact `Content-Range`), AV1 brand, on-demand sizes stored, sprite symbol count and compression, 404, 400 and 405.
- Independent decode on `fr1` of files fetched from the live host (`ffprobe`, `ffmpeg -f null`): `1920w-2x-av1.mp4` is av1 3840x2160 yuv420p and decodes fully; `600w-1x-vp9.webm` is vp9 600x338; `1024w-2x-h264.mp4` is h264 2048x1152; the on-demand `w777.webp` is 777x437, `avif=w500-h300` is 500x300, `webp=s100` is 100x56, the alpha icon `s144` fallback is png 144x144 rgba; all 24 rungs of the 4K source probed with the expected size and codec. A 4:2:0 AVIF of the opaque test photo at 1440 px is 36,524 B against 44,660 B WebP and 71,793 B JPEG.
- Determinism: re-encoding the same sources gave the same 7,054,344 B for the 24 rungs of the wide video.
- Headers (curl): pinned objects `Cache-Control: public, max-age=31536000, immutable`, negotiated images `Vary: Accept` with `s-maxage=3600`, `Accept-Ranges: bytes`, `Access-Control-Allow-Origin: *`, `Timing-Allow-Origin: *`, `Cross-Origin-Resource-Policy: cross-origin`, `alt-svc: h3`. Sprite with `Accept-Encoding: br`: `Content-Encoding: br`, 79,401 B on the wire for 283,371 B of SVG. A repeated GET of an image answers `CF-Cache-Status: HIT` and `X-Media-Source: edge-cache`.
- Chrome 150-class client on another origin (example.com): the negotiated `w1440` image and a pinned WebP load over `h3`, and Resource Timing reads their real sizes (`transferSize` 36,824 B and 12,206 B; googlebook returns 0 for its own cross-origin assets); `canPlayType` answers `probably` for the first three `<source>` types with `codecs=`.

## Resume
```
bun tools/media-cdn/fixtures.ts --out $WORK/fixtures                         # fr1
bun tools/media-cdn/build.ts --src $WORK/fixtures --out $WORK/out --jobs 3   # fr1, resumes
CLOUDFLARE_API_TOKEN=... bun tools/media-cdn/publish.ts --out <out>           # any host with the token
bun tools/media-cdn/verify.ts
cd cloudflare/media-cdn && bun run deploy
```
