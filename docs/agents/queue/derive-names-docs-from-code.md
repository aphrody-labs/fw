# Queued lot: Nix-like naming and code-derived docs (after the Phase 1 unification)

User directives (2026-11-21):
- rename every crate, prefix, scope, path, doc, skill and URL in a reproducible, flexible, configurable, Nix-like way, with nothing frozen or hardcoded;
- docs, files, memory, skills, rules, refs and agent sessions come from the real code and products in real time, with no legacy.

## Inputs that exist today

- `naming.toml` in aphrody (`id = "aphrody"`, `kind = "os"`, `org = "aphrody-dev"`, `[names] upstream = true`).
- `naming.toml` in ay (`kind = "sdk"`, `[legacy]` npm/crate lists, `[absorbed] auto = { crate_prefix = "auto-", npm_scope = "@aphrody", npm_prefix = "auto-" }`).
- `naming.toml` in browser (`[legacy]`, `[exceptions]`).
- `product.toml` and `crates/brand` in aphrody.
- Generators: `plugins/aphrody/scripts/unify.ts`, `sync-modern-web.ts`, aphrody `site/build.ts`, `configs/claude/scripts/matrix.ts`.

## Deliverables

1. One root declarative config in the monorepo. It merges the `naming.toml` files and `product.toml` and defines:
   - the org;
   - per-layer crate prefixes and npm scopes;
   - path roots;
   - domains and subdomains;
   - hosts, by role and not by address;
   - versions.
   It allows overlays (like Nix overlays) per environment: PC, fr1, prd, gcloud, CI.
2. `fw gen` (Rust, in the fw CLI), which reads the config and the code and derives:
   - crate and package names (`Cargo.toml` `name`, `package.json` `name`), with a codemod for `use`/`import` sites;
   - path layout;
   - URLs in code and docs;
   - docs (API references from rustdoc JSON and TS types; command references from the CLIs' `--help`);
   - skills and rules (CLAUDE.md, GEMINI.md, AGENTS.md sections generated from the config and the code);
   - memory indexes;
   - the agent context for agy and Claude sessions.
   Every output carries a "generated by fw gen from <inputs>@<sha>" header.
3. `fw gen --check` in CI fails on any drift. A watcher (`fw gen --watch`) and the plugin cron regenerate the outputs on change.
4. A one-shot rename pass applied through the config: crates, scopes, paths and URLs. It is proven by `cargo check --workspace`, `bun check`, a link check on docs, and a skills load test (headless `claude -p` listing the skills).
5. Purge the hand-written copies that the generator replaces, which removes legacy.

## Gate

An independent `fw gen --check` and full build on the pushed SHA; zero hardcoded org, host or domain strings outside the config (measured with a grep gate); docs and skills regenerate identically from a clean checkout.
