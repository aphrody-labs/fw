## Identified: nsh

"nsh" in $WORKSPACE_ROOT/aphrody (.agents/plugins/aphrody/docs/nsh, skills/nsh, skills/nsh-design-guides) is **Native Shell (NSH)**, upstream https://github.com/longbridge/nsh (Apache-2.0, v0.5.1 2026-11-14, 2915 stars): a Rust native UI framework whose apps (TSX or Rust, QuickJS engine) render through each platform's own views (UIKit, Android views, AppKit, Win32, GTK 4), HTML on the web, GPUI inside GPUI apps, and cells in a terminal. Its docs also name a plugin ecosystem (longbridge/nsh-compat, huacnlee/nsh-platform-miniprogram). It is a different architecture from Rune: native widgets per platform versus Rune's single own GPU renderer.

## Rune (aphrody-labs/rune, fork of anomalyco/rune)

Read in depth: README, crates/rune/README.md (2976 lines), WEB.md, Cargo.toml, directory layout.

- Fork state: default branch dev, MIT, 0 stars on the fork, 7302 on anomalyco/rune; no tagged releases, consumers pin a rev of dev ("dev is never rewritten"). No upstream pull requests are accepted (issues only).
- Platforms: macOS, Windows, Linux and the web (experimental WebGPU canvas target, no SharedArrayBuffer or COOP/COEP needed, built with scripts/web-build.sh). iOS is not wired yet; Android is not mentioned in the READMEs read.
- Architecture: view function `fn view(s,&mut Cx) -> El` with keyed diff; Taffy 0.15 flexbox layout; Parley 0.12 text with embedded Inter 4.1 and per-OS glyph rasterization matching CoreText and DirectWrite; one instanced uber-quad wgpu pipeline (rounded rects, analytic shadows, gradients, vector shapes, images, glyphs); analytic spring animation (rune-motion); OKLCH design tokens.
- Agent features: every app runs headless, renders PNG, dumps the element tree and accepts scripted input (README); rune-perf records bounded local frame diagnostics.
- Layout of the repo: crates/ (rune, rune-kit components, rune-motion, rune-i18n, rune-fx, rune-light, rune-luau, rune-mermaid, rune-highlights, rune-knobs, rune-notify, rune-perf, rune-taffy, rune-mac, procwatch ...), examples/ (about 40: hello, settings, todo, kit-gallery, launcher, video-player, web-hello, web-showcase ...), themes/opencode, vendor/ (patched wgpu-hal, winit, accesskit_macos, accesskit_windows, parley_engine, tiny-skia-path), site/, www/, research/, spikes/, scripts/.
- Measured by the project (Apple silicon, loaded laptop): first content about 299 to 312 ms after open; settled memory of one settings window 70 MB after an idle-draw fix. No Windows or Linux numbers, no binary size.

## Recommendation per Aphrody surface

Basis: only the facts above; the choices are judgement, not benchmark winners (no cross-framework benchmark exists in the sources read). The owner's standing rule is Rust core and no fixed framework, so each pick is a default to revisit when numbers exist.

1. **OS shell (desktop shell, launcher, system chrome)**: GPUI as primary candidate (Rust, GPU accelerated, Linux, Windows and macOS with Wayland and X11 features, Apache-2.0 crate, 95k stars on the Zed repo, pre-1.0 so pin a rev), with Rune as the second candidate (own wgpu renderer, headless agent testing, launcher and overlay examples exist, but no Linux or Windows startup numbers and no iOS). libcosmic is the reference for a Linux-only Wayland shell (MPL-2.0, experimental a11y) but is Linux-only. Qt 6 is the only option here with mature widely documented a11y and i18n, at LGPL or commercial licence cost.
2. **Craft native UI (apps with rich motion and GPU effects)**: Rune (fork already under aphrody-labs; motion, effects, tokens, kit components, headless PNG and tree inspection suit the agent-first loop). Risks to close before committing: accessibility coverage is unaudited (accesskit vendored for macOS and Windows only), i18n crate unread, no mobile. Fallback: GPUI or Slint (Slint has AccessKit and Live Preview, but tri-licence terms apply).
3. **Web products**: SvelteKit on Bun (Bun fullstack with HTML imports for lean apps, SvelteKit adapters for deploys) as default; Next.js where the React ecosystem is required (documented i18n and Fast Refresh); Leptos or Dioxus only where a Rust web codebase is mandated (Leptos 0.8.23 stable, Dioxus 0.7.10 stable, both with newer prereleases on crates.io).
4. **Mobile**: Compose Multiplatform for Android and iOS where Material 3 fidelity matters (Android is the first-party Jetpack Compose runtime; iOS shared UI; Web is Beta), Flutter 3.50.0 as the alternative with the broadest platform list in one engine, Expo or React Native if the TypeScript web codebase must be shared, Dioxus for a Rust-only team (webview-based). Rune and GPUI are not mobile options today (Rune iOS not wired; GPUI lists no mobile).
