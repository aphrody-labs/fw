# 4. RISC-V: registers, extensions, Linux syscalls, OpenSBI boot

RISC-V is an open instruction set built from a small mandatory base plus optional **extensions**. The 64-bit flavour used here is **RV64GC**: base integer ISA `I` (RV64I), plus `M` (multiply and divide), `A` (atomics), `F` and `D` (single and double floating point), `C` (16-bit compressed instructions), and `Zicsr` / `Zifencei` (CSR access, instruction-fetch fence); `G` is the shorthand for `IMAFD` with those two. The corelib is compiled for it with `clang --target=riscv64-unknown-elf -march=rv64gc -mabi=lp64d` (`tools/corelib.ts`); the object records the exact ISA string `rv64i2p1_m2p0_a2p1_f2p2_d2p2_c2p0_zicsr2p0_zmmul1p0_zaamo1p0_zalrsc1p0_zca1p0_zcd1p0` in its `.attribute` line (observed), where `zmmul`, `zaamo`/`zalrsc` and `zca`/`zcd` are the finer-grained pieces of `M`, `A` and `C`. Everything below was assembled with GNU binutils 2.47 and run on `fr1` with QEMU 11.0.3 and OpenSBI 1.8 on 2026-11-17, or generated by clang 23 from the C corelib (`corelib/src`).

## Registers

There are 32 integer registers `x0`-`x31`, each 64 bits wide on RV64, plus `pc`. The calling convention gives them names ([riscv-elf-psabi-doc, riscv-cc.adoc](https://github.com/riscv-non-isa/riscv-elf-psabi-doc/blob/master/riscv-cc.adoc), read 2026-11-17):

| Register | ABI name | Role | Preserved across calls |
|---|---|---|---|
| `x0` | `zero` | hard-wired zero | n/a |
| `x1` | `ra` | return address | no |
| `x2` | `sp` | stack pointer | yes |
| `x3` | `gp` | global pointer | not allocatable |
| `x4` | `tp` | thread pointer | not allocatable |
| `x5`-`x7` | `t0`-`t2` | temporaries | no |
| `x8`, `x9` | `s0`/`fp`, `s1` | saved (`s0` is also the frame pointer) | yes |
| `x10`-`x17` | `a0`-`a7` | arguments and results | no |
| `x18`-`x27` | `s2`-`s11` | saved | yes |
| `x28`-`x31` | `t3`-`t6` | temporaries | no |

Other state:

- **`pc`** is not an operand. `jal`, `jalr`, branches, `auipc` use it.
- **No flags register.** There is no carry, zero or overflow flag. Conditional branches **compare inside the branch**: `beq`, `bne`, `blt`, `bge`, `bltu`, `bgeu` take two registers and a label; `beqz`/`bnez` are `beq`/`bne` against `zero`. To get a boolean, `slt`, `sltu`, `slti`, `sltiu` write 0 or 1 into a register, and the assemblers provide `seqz rd, rs` (= `sltiu rd, rs, 1`) and `snez`.
- **Floating point:** `f0`-`f31` (`fa0`-`fa7` arguments), with the `lp64d` ABI passing doubles in them. The corelib uses none.
- **CSRs** (control and status registers) form a separate 12-bit address space, accessed only by `csrr rd, csr` (read), `csrw csr, rs` (write) and the atomic read-modify-write `csrrw`, `csrrs`, `csrrc`. Examples used below: `stvec` (trap vector), `sepc` (exception PC), `scause` (cause), `sstatus` (status, including `SPP` = previous privilege). The machine-mode twins are `mtvec`, `mepc`, `mcause`, `mstatus`; `satp` controls the MMU.
- **Privilege modes:** **M** (machine, always present: firmware), **S** (supervisor: the OS kernel), **U** (user). A trap goes to M-mode unless it was delegated to S-mode (`medeleg`/`mideleg`), and `mret`/`sret` return.

Fixed 32-bit instructions are the base; with `C` the common ones also exist as 16-bit forms, so instruction length is 2 or 4 bytes. Immediates are small (12 bits in `addi` and loads, 20 bits in `lui`/`auipc`), so a 32-bit constant is a `lui` + `addi` pair, and a PC-relative address is an `auipc` + `addi` pair (`la`/`lla` pseudo-instructions).

### Sign-extension and the `w` instructions

On RV64 a 32-bit value is kept **sign-extended** in its 64-bit register. Instructions with a `w` suffix (`addw`, `addiw`, `srliw`, `subw`, `slliw`) compute on the low 32 bits and sign-extend the result; that is how 32-bit C `uint32_t` arithmetic is done on a 64-bit machine. Plain `slli`, `xor`, `and`, `or` work on all 64 bits, which is harmless as long as a `w` operation follows. You will see both in `ay_checksum`.

## Extensions that matter for the listings

| Extension | What it adds | Where it shows up |
|---|---|---|
| `M` | `mul`, `div`, `rem` | `mul` in `ay_first_free` |
| `A` | `lr`/`sc` (load-reserved / store-conditional) and `amo*` (atomic read-modify-write, for example `amoswap`, `amoadd`) | `ay_try_acquire` |
| `C` | 16-bit encodings | invisible in listings; `clang -S` prints the full mnemonic |
| `Zbb` | basic bit-manipulation: rotates `rol`/`ror`/`rori`, `clz`/`ctz`/`cpop`, `andn`/`orn`/`xnor`, `min`/`max`, sign extensions | **not** in the baseline target; shown below with `-march=rv64gc_zbb` |
| `Zacas` | compare-and-swap `amocas` | not in the baseline; shown below |

`riscv64gc` has no rotate, no count-trailing-zeros and no `andn`. That is why the RISC-V listings differ most from the other two ISAs.

### A complete program, no libc

<!-- listing file:corelib/asm/hello_linux_riscv64.s -->
```asm

# Syscall ABI: number in a7, arguments in a0..a5, `ecall` traps to the kernel, result in a0.
# Build: riscv64-linux-gnu-as hello_linux_riscv64.s -o hello.o && riscv64-linux-gnu-ld hello.o -o hello

	.set	msg_len, . - msg

	.text
_start:
	li	a0, 1			# fd 1 = stdout
	lla	a1, msg			# buffer, PC-relative (auipc + addi)
	li	a2, msg_len		# byte count
	li	a7, 64			# __NR_write
	ecall
	li	a0, 0			# status 0
	li	a7, 94			# __NR_exit_group
	ecall
```

   100b4:	00000597          	auipc	a1,0x0

   100bc:	01200613          	li	a2,18

The `msg_len` constant had to be defined **before** its use in this file: `li a2, msg_len` with a forward reference failed (`illegal operands`), because GNU `as` must know the value at that point to pick the instruction sequence.

## The same functions, compiled

Regenerated by `bun tools/listings.ts` from `corelib/src` with `clang -S -O2 -std=c23 -ffreestanding --target=riscv64-unknown-elf -march=rv64gc -mabi=lp64d` (flags in `tools/corelib.ts`). Labels such as `.LBB0_2` are compiler-internal.

### `ay_rights_allow`: no flags, no `andn`

<!-- listing c:corelib/src/abi.c#ay_rights_allow -->
```c
/// Whether a capability holding `have` may perform an operation that needs `need`.
AY_API uint32_t ay_rights_allow(uint32_t have, uint32_t need) { return (have & need) == need; }
```
<!-- /listing -->
<!-- listing asm:ay_rights_allow:riscv64 -->
```asm
ay_rights_allow:
	and	a0, a0, a1
	xor	a0, a0, a1
	seqz	a0, a0
	ret
```
<!-- /listing -->

`(have & need) == need` is computed as `(have & need) ^ need` (zero when the right is held), then `seqz a0, a0` produces the boolean: three ALU instructions and no flags. The base ISA has no and-not instruction. With `-march=rv64gc_zbb` the same function becomes `andn a0, a1, a0` (`need & ~have`) plus `seqz` (observed with clang 23.1.5, not part of the generated listings).

### `ay_first_free`: no `ctz`, so a de Bruijn table

<!-- listing c:corelib/src/mem.c#ay_first_free -->
```c
/// Index of the lowest clear bit, or -1 when all 64 are set: the first free frame.
AY_API int32_t ay_first_free(uint64_t bits) {
  if (!~bits) return -1;
  return __builtin_ctzll(~bits);
}
```
<!-- /listing -->
<!-- listing asm:ay_first_free:riscv64 -->
```asm
ay_first_free:
	not	a0, a0
	beqz	a0, .LBB0_2
	lui	a1, %hi(.LCPI0_0)
	ld	a1, %lo(.LCPI0_0)(a1)
	neg	a2, a0
	and	a0, a0, a2
	mul	a0, a0, a1
	srli	a0, a0, 58
	lui	a1, %hi(.LCPI0_1)
	addi	a1, a1, %lo(.LCPI0_1)
	add	a0, a0, a1
	lbu	a0, 0(a0)
	ret
.LBB0_2:
	li	a0, -1
	ret
.LCPI0_0:
	.quad	151050438420815295
.LCPI0_1:
	.ascii	"\000\001\002\007\003\r\b\023\004\031\016\034\t\"\024(\005\021\032&\017.\0350\n\037#6\0252)9?\006\f\022\030\033!'\020%-/\036518>\013\027 $,47=\026+3<*;:"
```
<!-- /listing -->

Without `Zbb` there is no count-trailing-zeros instruction, and without `clz` the `rbit`+`clz` trick of AArch64 is not available either, so `__builtin_ctzll` is expanded with the classic **de Bruijn multiplication**:

1. `not a0, a0` makes free frames ones; `beqz a0, .LBB0_2` is the `if (!~bits) return -1` of the source, and the target block is just `li a0, -1`.
2. `neg a2, a0` and `and a0, a0, a2` compute `x & -x`, which keeps only the lowest set bit.
3. `mul a0, a0, a1` multiplies by the 64-bit de Bruijn constant `0x0218A392CD3D5DBF` (the `.quad 151050438420815295` after the function, loaded with `lui` + `ld` and the `%hi`/`%lo` relocations). Multiplying a single bit `2^k` by it shifts the constant left by `k`.
4. `srli a0, a0, 58` takes the top 6 bits, which are unique for each `k`, and `lbu` looks the index up in a 64-byte table (`.LCPI0_1`).

The addresses of the constant and of the table are formed with `lui` + `addi`/`ld` and `%hi`/`%lo`: this build uses the default absolute (medlow) code model, which reaches the low and the high 2 GiB of the address space with two instructions, instead of the PC-relative `auipc` pair that a position-independent build would use.

With `-march=rv64gc_zbb` the whole function shrinks to `sltiu a1, a0, -1; not a0, a0; ctz a0, a0; addi a1, a1, -1; or a0, a0, a1; ret` (observed with clang 23.1.5): the multiply, the loads, the table and the branch disappear. `sltiu a1, a0, -1` compares the original bitmap, unsigned, with all ones (the immediate is sign-extended to 64 bits), giving 1 unless the bitmap is full; `addi a1, a1, -1` turns that into 0 or all ones, and `or` forces -1 for a full bitmap.

### `ay_arg_count`: the same byte table

<!-- listing c:corelib/src/abi.c#ay_arg_count -->
```c
/// Number of arguments each syscall reads (0 for an unknown number).
AY_API uint32_t ay_arg_count(uint32_t nr) {
  switch (nr) {
  case AY_SYS_VERSION:
  case AY_SYS_YIELD:
  case AY_SYS_FRAME_ALLOC:
    return 0;
  case AY_SYS_CAP_DROP:
  case AY_SYS_SEND:
  case AY_SYS_RECV:
  case AY_SYS_MSG_GET:
  case AY_SYS_FRAME_FREE:
    return 1;
  case AY_SYS_MSG_SET:
  case AY_SYS_CAP_DERIVE:
    return 2;
  case AY_SYS_LOG:
    return 3;
  default:
    return 0;
  }
}
```
<!-- /listing -->
<!-- listing asm:ay_arg_count:riscv64 -->
```asm
ay_arg_count:
	li	a1, 8
	addiw	a0, a0, -2
	bltu	a1, a0, .LBB2_2
	lui	a1, %hi(.Lswitch.table.ay_arg_count)
	addi	a1, a1, %lo(.Lswitch.table.ay_arg_count)
	add	a0, a0, a1
	lbu	a0, 0(a0)
	ret
.LBB2_2:
	li	a0, 0
	ret
.Lswitch.table.ay_arg_count:
	.ascii	"\003\002\001\001\001\002\001\000\001"
```
<!-- /listing -->

`addiw a0, a0, -2` rebases the number (as a 32-bit `w` operation), `li a1, 8` and `bltu a1, a0, ...` is the unsigned range check written as a compare-and-branch (8 < index means out of range), and the byte table (`.Lswitch.table.ay_arg_count`) is addressed with `lui` + `addi` (`%hi` / `%lo`), then `add` and `lbu`. RISC-V has no scaled or indexed addressing mode, so the index is added to the base in a separate instruction, where x86-64 and AArch64 fold it into the load.

### `ay_checksum`: rotate by hand

<!-- listing c:corelib/src/ipc.c#ay_checksum -->
```c
/// Rotate-and-add checksum of a message; the loop shows how each ISA spells a rotate.
AY_API uint32_t ay_checksum(const uint32_t *words, size_t len) {
  uint32_t acc = 0x811C9DC5u;
  for (size_t i = 0; i < len; i++) {
    acc = (((acc << 5) | (acc >> 27)) + words[i]) ^ 0x9E3779B9u;
  }
  return acc;
}
```
<!-- /listing -->
<!-- listing asm:ay_checksum:riscv64 -->
```asm
ay_checksum:
	lui	a3, 528842
	beqz	a1, .LBB0_4
	slli	a1, a1, 2
	lui	a4, 648056
	add	a2, a0, a1
	addi	a1, a3, -571
	addi	a3, a4, -1607
.LBB0_2:
	lw	a4, 0(a0)
	srliw	a5, a1, 27
	slli	a1, a1, 5
	or	a1, a1, a5
	addw	a1, a1, a4
	addi	a0, a0, 4
	xor	a1, a1, a3
	bne	a0, a2, .LBB0_2
	mv	a0, a1
	ret
.LBB0_4:
	addi	a0, a3, -571
	ret
```
<!-- /listing -->

`(acc << 5) | (acc >> 27)` on a 32-bit value is three instructions without `Zbb`: `srliw a5, a1, 27` (the 5 bits that wrap around), `slli a1, a1, 5` (the shifted body) and `or a1, a1, a5`. `slli` is a 64-bit shift and leaves garbage above bit 31, which the next `addw a1, a1, a4` removes by computing on the low 32 bits and sign-extending. With `-march=rv64gc_zbb` the three instructions become one, `roriw a1, a1, 27` (rotate right by 27 = rotate left by 5; observed with clang 23.1.5). The constants are `lui` + `addi` pairs: `lui a3, 528842` loads `0x811CA000` and `addi a1, a3, -571` subtracts `0x23B` to get `0x811C9DC5`; the low half `0x9DC5` has bit 11 set, so `addi` (a *signed* 12-bit immediate) would add a negative number and `lui` is therefore one higher than the top bits of the constant. The loop compares the advancing pointer with an end pointer (`bne a0, a2`) instead of counting down, because compare-and-branch needs no flags. This loop is not unrolled in the build either (it is on x86-64).

### `ay_try_acquire`: `lr` / `sc`

<!-- listing c:corelib/src/sync.c#ay_try_acquire -->
```c
/// Take the lock word 0 -> 1; true when this caller now holds it.
AY_API uint32_t ay_try_acquire(uint32_t *flag) {
  uint32_t expected = 0;
  return atomic_compare_exchange_strong_explicit((_Atomic uint32_t *)flag, &expected, 1u, memory_order_acquire,
                                                 memory_order_relaxed);
}
```
<!-- /listing -->
<!-- listing asm:ay_try_acquire:riscv64 -->
```asm
ay_try_acquire:
	li	a1, 1
.LBB0_1:
	lr.w.aq	a2, (a0)
	bnez	a2, .LBB0_3
	sc.w	a3, a1, (a0)
	bnez	a3, .LBB0_1
.LBB0_3:
	seqz	a0, a2
	ret
```
<!-- /listing -->

The `A` extension has atomic read-modify-write instructions (`amoswap`, `amoadd`, `amoand`...), but no compare-and-swap, so LLVM uses the **load-reserved / store-conditional** pair. `lr.w.aq a2, (a0)` loads the lock word with **acquire** ordering (`.aq`) and registers a reservation on that address; `bnez a2, .LBB0_3` leaves if the lock is held; `sc.w a3, a1, (a0)` stores 1 only if the reservation is still valid and writes 0 to `a3` on success (non-zero if the reservation was lost), and `bnez a3, .LBB0_1` retries. `seqz a0, a2` converts the loaded value into the boolean: 1 when the old value was 0. The acquire bit goes on the `lr`, so no separate fence is needed. With `Zacas` the function is one instruction (`-march=rv64gc_zacas`, observed with clang 23.1.5): `li a1, 0; li a2, 1; amocas.w.aq a1, a2, (a0); seqz a0, a1; ret`.

## Booting RISC-V on QEMU `virt` with OpenSBI

A RISC-V platform boots through firmware in M-mode. On QEMU `virt` that is **OpenSBI** (`-bios default`; here the `fw_dynamic` build from Ubuntu's `opensbi` package, version 1.8). It initializes the machine, sets up trap delegation, and then jumps to the next stage in **S-mode** at the kernel address with `a0` = the hart (hardware thread) id and `a1` = the address of the device tree. The S-mode software talks back to the firmware through the **SBI** (Supervisor Binary Interface): an `ecall` from S-mode traps into M-mode, where OpenSBI handles it.

The SBI calling convention ([riscv-sbi-doc binary-encoding](https://github.com/riscv-non-isa/riscv-sbi-doc/blob/master/src/binary-encoding.adoc), read 2026-11-17): `a7` = extension ID (EID), `a6` = function ID (FID), `a0`-`a5` arguments, results in `a0` (error) and `a1` (value), every other register preserved. The example uses two extensions: the **legacy console putchar** (EID `0x01`, a byte in `a0`; the SBI specification marks the legacy extensions as deprecated) and **SRST** (EID `0x53525354`, "SRST"; function 0 `sbi_system_reset`, `a0` = reset type 0 = shutdown, `a1` = reason).

Memory map from QEMU's [hw/riscv/virt.c](https://github.com/qemu/qemu/blob/master/hw/riscv/virt.c) (`virt_memmap`, read 2026-11-17): the **16550-compatible UART0 at `0x10000000`**, DRAM from `0x80000000`. OpenSBI occupies the start of DRAM; the kernel is loaded at `0x80200000` (OpenSBI banner below: `Domain0 Next Address`). The UART register layout is the same as in chapter 2: transmit holding register at offset 0, line status register at offset 5, bit 5 (`0x20`) = THRE, transmitter ready.

<!-- listing file:corelib/asm/boot_virt_riscv64.s -->
```asm
# Bare-metal RV64 for QEMU `-M virt`: OpenSBI hands over in S-mode at 0x80200000 with a0 = hart id, a1 = device tree.
# Build: riscv64-linux-gnu-as boot_virt_riscv64.s -o boot.o && riscv64-linux-gnu-ld -N --no-warn-rwx-segments -nostdlib -Ttext=0x80200000 boot.o -o boot.elf
# (`-N` keeps the ELF header out of the loaded segment: QEMU hands the lowest loaded address to OpenSBI as the S-mode entry.)
# Run:   qemu-system-riscv64 -M virt -nographic -bios default -kernel boot.elf
	.option	norvc			# fixed 4-byte instructions, so the trap handler can step over ebreak with sepc += 4
	.equ	UART0, 0x10000000	# 16550 on the virt board: THR at +0, LSR at +5
	.equ	LSR_THRE, 0x20		# transmit holding register empty

	.text
	.globl	_start
_start:
	la	sp, stack_top
	la	t0, trap
	csrw	stvec, t0		# direct mode: every trap enters at `trap`

	la	a0, msg_hart
	call	puts

	la	a0, msg_sbi
	call	puts_sbi

	ebreak				# breakpoint exception, delegated to S-mode by OpenSBI
	la	a0, msg_back
	call	puts

	li	a7, 0x53525354		# SBI SRST extension ("SRST")
	li	a6, 0			# function 0: system_reset
	li	a0, 0			# type 0: shutdown
	li	a1, 0			# reason 0: none
	ecall
1:	wfi
	j	1b

putc:					# a0 = byte; clobbers t0, t1
	li	t0, UART0
1:	lbu	t1, 5(t0)
	andi	t1, t1, LSR_THRE
	beqz	t1, 1b			# wait until the transmitter can take a byte
	sb	a0, 0(t0)
	ret

puts:					# a0 = NUL-terminated string; clobbers t0-t2, a0
	addi	sp, sp, -16
	sd	ra, 0(sp)
	mv	t2, a0
1:	lbu	a0, 0(t2)
	beqz	a0, 2f
	call	putc
	addi	t2, t2, 1
	j	1b
2:	ld	ra, 0(sp)
	addi	sp, sp, 16
	ret

puts_sbi:				# same output through the SBI legacy console, EID 0x01, one byte per ecall
	mv	t2, a0
1:	lbu	a0, 0(t2)
	beqz	a0, 2f
	li	a7, 1			# sbi_console_putchar
	ecall				# S-mode -> M-mode (OpenSBI)
	addi	t2, t2, 1
	j	1b
2:	ret

	.balign	4
trap:					# scause = 3 is a breakpoint
	csrr	t0, scause
	li	t1, 3
	bne	t0, t1, hang
	la	a0, msg_trap
	call	puts
	csrr	t0, sepc
	addi	t0, t0, 4		# skip the 4-byte ebreak
	csrw	sepc, t0
	sret				# back to sepc in the privilege mode saved in sstatus.SPP
hang:	j	hang

	.section .rodata
msg_hart: .asciz "hello from RISC-V S-mode via the 16550\n"
msg_sbi:  .asciz "hello again via SBI console_putchar\n"
msg_trap: .asciz "caught ebreak (scause == 3)\n"
msg_back: .asciz "returned from the handler, shutting down\n"

	.bss
	.balign	16
	.skip	4096
stack_top:
```
<!-- /listing -->

How it works:

- `la sp, stack_top` builds the stack address (`auipc` + `addi`; the loader gives none). `la t0, trap` / `csrw stvec, t0` installs the trap handler; the two low bits of `stvec` are the mode, 0 = **direct** (all traps enter at the same address).
- `putc` polls `LSR` bit 5 with `lbu`/`andi`/`beqz` and stores the byte with `sb`. It writes the UART directly, which works because OpenSBI's PMP (physical memory protection) configuration lets S-mode access that range: the banner lists `Domain0 Region03 : 0x0000000010000000-0x0000000010000fff M: (I,R,W) S/U: (R,W)`.
- `puts_sbi` prints the same way through `ecall` with `a7 = 1`.
- `ebreak` raises a breakpoint exception, cause 3. OpenSBI delegates it to S-mode (the banner prints `Boot HART MEDELEG : 0x0000000000f4b509`; bit 3 is set), so it lands in our `trap`. The handler checks `scause`, prints, adds 4 to `sepc` (the instruction length, guaranteed by `.option norvc`; with the `C` extension an assembler may emit the 2-byte `c.ebreak`) and returns with `sret`.
- The shutdown goes through SRST. `li a7, 0x53525354` is `lui` + `addiw` in the disassembly. QEMU exits with status 0.

**A trap in the link step.** The first build used plain `ld -Ttext=0x80200000`. The ELF then has a loadable segment that starts one page earlier (`0x801ff000`), because the ELF header and program headers are mapped with the text. QEMU hands the **lowest loaded address** to OpenSBI as the next-stage entry, and the banner showed `Domain0 Next Address : 0x00000000801ff000`: the CPU would execute the ELF header and the example printed none of its lines before the 20-second timeout. `ld -N` (no page alignment, one RWX segment) keeps the header out of the loaded segment, so `Next Address` is `0x80200000` and `_start` is the first instruction. `--no-warn-rwx-segments` silences the resulting linker warning.

The LLVM toolchain gives the same results (observed on fr1): `clang --target=riscv64-linux-gnu -march=rv64gc -c hello_linux_riscv64.s` + `ld.lld` runs under `qemu-riscv64`, and `clang --target=riscv64-unknown-elf -march=rv64gc -c boot_virt_riscv64.s` + `ld.lld -N -Ttext=0x80200000` boots to the same four lines with exit status 0 (`ld.lld` has no `--no-warn-rwx-segments` option and needs none). `tools/asm-examples.test.ts` rebuilds and runs both, with clang and `ld.lld` when present and GNU binutils otherwise, and checks the four lines.
