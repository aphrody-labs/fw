# 2. x86-64: registers, System V ABI, Linux syscalls, the real boot

x86-64 (AMD64, Intel 64) is a CISC instruction set with variable-length instructions, two-operand arithmetic (`add a, b` means `a += b`), memory operands inside ordinary instructions and a flags register. Everything in this chapter was assembled with GNU binutils 2.47 and run or disassembled on `<build-host>` (Ubuntu 26.10, Linux 7.3, x86-64) on 2026-11-17, or generated by clang 23 from the C corelib (`corelib/src`, `--target=x86_64-unknown-none-elf`; flags in `tools/corelib.ts`).

## Registers

| Group | Registers | Notes |
|---|---|---|
| General purpose, 64 bit | `rax rbx rcx rdx rsi rdi rbp rsp r8`-`r15` | 16 registers |
| Views | 32 bit `eax`..`r15d`, 16 bit `ax`..`r15w`, 8 bit `al`, `sil`, `r8b` (and legacy `ah`..`bh`) | Writing a **32-bit** view zero-extends into the full 64-bit register; writing an 8- or 16-bit view leaves the other bits alone. That is why `xor eax, eax` clears all of `rax` and `mov ecx, edx` in `ay_checksum` below is a clean 64-bit zero-extension |
| Instruction pointer | `rip` | Not writable by `mov`; changed by `jmp`, `call`, `ret`. Readable as an address base: `[rip + sym]` |
| Flags | `rflags` | Bit 0 CF carry, 2 PF parity, 6 ZF zero, 7 SF sign, 9 IF interrupts, 10 DF direction, 11 OF overflow |
| Segment | `cs ds es ss fs gs` | In 64-bit mode the bases of `cs ds es ss` are ignored; `fs` and `gs` keep a base, set through MSRs, and carry thread-local data. `cs` still selects the privilege level and, through its descriptor, whether the code runs in 64-bit mode (see the boot below) |
| Control | `cr0` (bit 0 PE protection, bit 16 WP write-protect, bit 31 PG paging), `cr2` (faulting address), `cr3` (page-table root), `cr4` (bit 4 PSE, bit 5 PAE) | Only ring 0 can touch them |
| Model-specific | `IA32_EFER` = MSR `0xC0000080`: bit 0 SCE (`syscall` enable), bit 8 LME (long mode enable), bit 10 LMA (long mode active, read-only), bit 11 NXE (no-execute enable) | Read with `rdmsr`, written with `wrmsr`, both with the MSR number in `ecx` |

Bit numbers are taken from the Linux headers `processor-flags.h` and `msr-index.h` (sources at the end) and checked against the boot code below, which sets exactly CR4 bit 5, EFER bit 8 and CR0 bit 31.

## Intel and AT&T syntax

The same bytes have two spellings. Intel puts the **destination first** and writes size as a prefix on memory operands; AT&T (the GNU default) puts the destination **last**, prefixes registers with `%` and immediates with `$`, and encodes the size in the mnemonic suffix. The guide uses Intel syntax: clang is run with `-masm=intel` by `tools/corelib.ts`, and the hand-written files start with `.intel_syntax noprefix`.

| Intel | AT&T (`objdump -M att` on the same bytes) |
|---|---|
| `mov eax, 1` | `mov $0x1,%eax` |
| `lea rsi, [rip + msg]` | `lea 0xfef(%rip),%rsi` |
| `add eax, dword ptr [rdi + 4*rdx]` | `add (%rdi,%rdx,4),%eax` |
| `movzx eax, byte ptr [rax + rcx]` | `movzbl (%rax,%rcx,1),%eax` |
| `rol eax, 5` | `rol $0x5,%eax` |
| `lock cmpxchg dword ptr [rdi], edx` | `lock cmpxchg %edx,(%rdi)` |

A trap of Intel syntax in GNU `as`: a bare symbol is a **memory** operand. `mov edx, msg_len` would load from the address `msg_len`; the example below needs `mov edx, offset msg_len` for the constant. The first version of the example in this repository crashed with a segmentation fault for exactly this reason.

## Addressing modes

An operand is a register, an immediate or a memory reference `[base + index*scale + displacement]` with scale 1, 2, 4 or 8, every part optional. In 64-bit mode `[rip + disp32]` addresses relative to the next instruction, which makes code position-independent. The listings use three shapes:

- `dword ptr [rdi + 4*rdx]`: element `rdx` of a `u32` array (the loop in `ay_checksum`);
- `byte ptr [rax + rcx]`: byte `rax` of a table whose address is in `rcx` (`ay_arg_count`);
- `[rip + .Lswitch.table.ay_arg_count]`: a read-only table next to the code.

`lea` computes an address and stores it without touching memory, so the compiler also uses it for arithmetic: `lea rdx, [r8 + 1]` is an addition that does not modify flags.

## Flags and conditional jumps

Most arithmetic and logic instructions write flags; `cmp a, b` is a subtraction that keeps only the flags, `test a, b` an AND that keeps only the flags. A conditional jump, `setcc` or `cmovcc` then reads them:

| After `cmp a, b` | Unsigned | Signed |
|---|---|---|
| a == b | `je` (ZF=1) | `je` |
| a != b | `jne` | `jne` |
| a < b | `jb` (CF=1) | `jl` (SF != OF) |
| a > b | `ja` (CF=0 and ZF=0) | `jg` |

The listings use `ja`, `jb`, `jne` and `je` on unsigned counters, `sete al` (set a byte to ZF) and `cmovb` (move if CF=1).

## Encoding sizes

Instructions are 1 to 15 bytes ([Intel SDM vol. 2](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html)). Real encodings from the disassembly of the five functions below (assembled with `as`) and of the example program (`objdump -d -M intel`, <build-host>):

| Bytes | Instruction | Size | Why |
|---|---|---|---|
| `c3` | `ret` | 1 | no operands |
| `31 c0` | `xor eax, eax` | 2 | opcode + ModRM; shorter than `mov eax, 0` (5 bytes) |
| `0f 05` | `syscall` | 2 | two-byte opcode |
| `c1 c0 05` | `rol eax, 5` | 3 | opcode + ModRM + imm8 |
| `b8 01 00 00 00` | `mov eax, 1` | 5 | opcode `b8`+reg, imm32 |
| `48 8d 35 ef 0f 00 00` | `lea rsi, [rip+0xfef]` | 7 | REX.W prefix + opcode + ModRM + disp32 |
| `f0 0f b1 17` | `lock cmpxchg [rdi], edx` | 4 | `lock` prefix + two-byte opcode + ModRM |
| `55` | `push rbp` | 1 | opcode `50`+reg, no ModRM |
| `48 89 e5` | `mov rbp, rsp` | 3 | REX.W + opcode + ModRM |
| `f3 48 0f bc c8` | `tzcnt rcx, rax` (the listing prints it as `rep bsf`) | 5 | `f3` prefix + REX.W + two-byte opcode + ModRM |
| `0f b6 80` + disp32 | `movzx eax, byte ptr [rax + table]` | 7 | two-byte opcode + ModRM + 32-bit displacement (the table address, filled in by the linker) |

## System V AMD64 calling convention

Used by Linux, BSD and macOS on x86-64 ([x86-64 psABI](https://gitlab.com/x86-psABIs/x86-64-ABI), `low-level-sys-info.tex`, read 2026-11-17).

| Role | Registers |
|---|---|
| Integer and pointer arguments, in order | `rdi rsi rdx rcx r8 r9`, the rest on the stack |
| Return value | `rax` (`rdx:rax` for 128 bits); floating point in `xmm0`/`xmm1` |
| Caller-saved (may be destroyed by a call) | `rax rcx rdx rsi rdi r8-r11` and the vector registers |
| Callee-saved (must be restored) | `rbx rbp r12 r13 r14 r15` and `rsp` |
| Stack | grows down; `call` pushes the return address, so at function entry `rsp` is 8 modulo 16 |

The five pure functions of the corelib take their arguments in `edi`, `esi`, `rdi`, `rsi` and return in `eax`/`rax`. Every temporary fits in a caller-saved register, so the only stack use is the frame-pointer prologue: the listings begin with `push rbp` / `mov rbp, rsp` and end with `pop rbp` because clang keeps frame pointers by default for this freestanding target. With `-fomit-frame-pointer` the same `ay_rights_allow` is just `not edi; xor eax, eax; test edi, esi; sete al; ret` (observed). A function that calls another one needs a real frame: `kmain` of the boot image starts with `push rbp; mov rbp, rsp; sub rsp, 0x10` (16 bytes for the console descriptor it passes by address), which keeps `rsp` 16-byte aligned at its own `call`. The image is built with `-mno-red-zone` (the 128 bytes below `rsp` that the psABI lets leaf functions use freely would be overwritten by an interrupt in kernel code) and `-mgeneral-regs-only` (no SSE or x87 instruction is ever emitted, so interrupt handlers need not save vector state); both flags are in `tools/corelib.ts` and are also applied to the listings.

## Linux syscall ABI

A user-space process enters the kernel with the `syscall` instruction ([syscall(2)](https://man7.org/linux/man-pages/man2/syscall.2.html), table row x86-64, read 2026-11-17):

| Item | Register |
|---|---|
| Syscall number | `rax` (`write` = 1, `exit_group` = 231; [syscall_64.tbl](https://github.com/torvalds/linux/blob/master/arch/x86/entry/syscalls/syscall_64.tbl)) |
| Arguments | `rdi rsi rdx r10 r8 r9` (`r10`, not `rcx`) |
| Result | `rax`; a value in `-4095..-1` is `-errno` (`MAX_ERRNO` = 4095 in the kernel header `include/linux/err.h`) |
| Clobbered by the instruction | `rcx` (return `rip`) and `r11` (saved `rflags`) ([entry_64.S](https://github.com/torvalds/linux/blob/master/arch/x86/entry/entry_64.S): "SYSCALL saves rip to rcx ... then saves rflags to r11") |

The 64-bit syscall numbers differ from 32-bit `int 0x80` and from AArch64 and RISC-V, which use the generic table (`write` = 64, `exit_group` = 94).

### A complete program, no libc

```asm
# Syscall ABI: number in rax, arguments in rdi rsi rdx r10 r8 r9, `syscall` clobbers rcx and r11, result in rax.
# Build: as hello_linux_x86_64.s -o hello.o && ld hello.o -o hello

	.section .rodata

	.set	msg_len, . - msg

	mov	edi, 1			# fd 1 = stdout

	syscall
	mov	eax, 231		# __NR_exit_group
	xor	edi, edi		# status 0
	syscall
```

## The same functions, compiled

Every listing below is regenerated by `bun tools/listings.ts` from `corelib/src` with `clang -S -O2 -std=c23 -ffreestanding --target=x86_64-unknown-none-elf -masm=intel -mgeneral-regs-only -mno-red-zone` (the flags of the bare-metal image, from `tools/corelib.ts`). Labels such as `.LBB0_9` are compiler-internal and stay stable only for a given clang.

### `ay_rights_allow`: flags and `setcc`

<!-- listing c:corelib/src/abi.c#ay_rights_allow -->
```c
/// Whether a capability holding `have` may perform an operation that needs `need`.
AY_API uint32_t ay_rights_allow(uint32_t have, uint32_t need) { return (have & need) == need; }
```
<!-- /listing -->
<!-- listing asm:ay_rights_allow:x86_64 -->
```asm
ay_rights_allow:
	push	rbp
	mov	rbp, rsp
	not	edi
	xor	eax, eax
	test	edi, esi
	sete	al
	pop	rbp
	ret
```
<!-- /listing -->

`have & need == need` compiles to `not edi` (invert `have`), `test edi, esi` (AND with `need`, flags only) and `sete al` (copy ZF into the low byte of `eax`). The compiler turned `(have & need) == need` into `(~have & need) == 0`, which needs no compare. The `xor eax, eax` sits **before** the `test` on purpose: `xor` writes flags, so placed after it would destroy the result, and `sete` writes only `al` and needs the upper bits already zero.

### `ay_first_free`: `tzcnt`

<!-- listing c:corelib/src/mem.c#ay_first_free -->
```c
/// Index of the lowest clear bit, or -1 when all 64 are set: the first free frame.
AY_API int32_t ay_first_free(uint64_t bits) {
  if (!~bits) return -1;
  return __builtin_ctzll(~bits);
}
```
<!-- /listing -->
<!-- listing asm:ay_first_free:x86_64 -->
```asm
ay_first_free:
	push	rbp
	mov	rbp, rsp
	mov	rax, rdi
	not	rax
	rep		bsf	rcx, rax
	xor	rdi, -1
	mov	eax, -1
	cmovne	eax, ecx
	pop	rbp
	ret
```
<!-- /listing -->

The C source is `if (!~bits) return -1; return __builtin_ctzll(~bits);`: `__builtin_ctzll` is undefined for zero, so the full-bitmap case is tested first. Clang computes `~bits` twice: `not rax` feeds the bit scan, and `xor rdi, -1` repeats the inversion only because `xor` (unlike `not`) writes the flags, so ZF tells whether the result is zero. `mov eax, -1` is placed between them because `mov` never writes flags, and `cmovne eax, ecx` selects the index unless the inversion gave zero.

The listing prints `rep bsf rcx, rax`. The bytes are `f3 48 0f bc c8`, which GNU `as`/`objdump` disassemble as `tzcnt rcx, rax`. `tzcnt` is `bsf` with an `f3` prefix: on a CPU with BMI1 it executes as `tzcnt`; on an older CPU the prefix is ignored and it executes as `bsf`. For a non-zero source both give the same index, and the zero case never reaches the instruction's result, so the baseline `x86_64` target can use the encoding that works everywhere. Compiled with `-mbmi` the same function differs in one mnemonic (observed with clang 23.1.5): `mov rax, rdi; not rax; tzcnt rcx, rax; xor rdi, -1; mov eax, -1; cmovne eax, ecx`.

### `ay_arg_count`: a lookup table instead of a jump table

<!-- listing c:corelib/src/abi.c#ay_arg_count -->
```c
/// Number of arguments each syscall reads (0 for an unknown number).
AY_API uint32_t ay_arg_count(uint32_t nr) {
  switch (nr) {
  case AY_SYS_VERSION:
  case AY_SYS_YIELD:
  case AY_SYS_FRAME_ALLOC:
    return 0;
  case AY_SYS_CAP_DROP:
  case AY_SYS_SEND:
  case AY_SYS_RECV:
  case AY_SYS_MSG_GET:
  case AY_SYS_FRAME_FREE:
    return 1;
  case AY_SYS_MSG_SET:
  case AY_SYS_CAP_DERIVE:
    return 2;
  case AY_SYS_LOG:
    return 3;
  default:
    return 0;
  }
}
```
<!-- /listing -->
<!-- listing asm:ay_arg_count:x86_64 -->
```asm
ay_arg_count:
	push	rbp
	mov	rbp, rsp
	add	edi, -2
	xor	eax, eax
	cmp	edi, 8
	ja	.LBB2_2
	mov	eax, edi
	movzx	eax, byte ptr [rax + .Lswitch.table.ay_arg_count]
.LBB2_2:
	pop	rbp
	ret
.Lswitch.table.ay_arg_count:
	.ascii	"\003\002\001\001\001\002\001\000\001"
```
<!-- /listing -->

The `switch` has nine consecutive numbers (2 to 10) mapping to small constants. Clang turns such a switch into a **byte table** (`.Lswitch.table.ay_arg_count`, nine bytes `3 2 1 1 1 2 1 0 1`: `LOG`=3, `MSG_SET`=2, `MSG_GET`=1, `SEND`=1, `RECV`=1, `CAP_DERIVE`=2, `CAP_DROP`=1, `FRAME_ALLOC`=0, `FRAME_FREE`=1). `add edi, -2` rebases the number, `cmp edi, 8` / `ja` is one unsigned range check that also rejects numbers 0 and 1 (they wrap to huge unsigned values), `xor eax, eax` pre-loads the default 0, and `movzx eax, byte ptr [rax + .Lswitch.table.ay_arg_count]` is the whole table read. The image is linked non-PIC in the small code model, so the table address is a 32-bit absolute displacement inside the instruction (`0f b6 80 disp32`) and no `lea rcx, [rip + ...]` is needed, unlike position-independent code. A **jump table** (an array of code addresses used by `jmp [table + idx*8]`) is the other lowering of a dense `switch`; LLVM picks it when the arms run different code rather than produce constants, and a table of constants is smaller and branch-free. This function has no jump table in the build.

### `ay_checksum`: `rol` and loop unrolling

<!-- listing c:corelib/src/ipc.c#ay_checksum -->
```c
/// Rotate-and-add checksum of a message; the loop shows how each ISA spells a rotate.
AY_API uint32_t ay_checksum(const uint32_t *words, size_t len) {
  uint32_t acc = 0x811C9DC5u;
  for (size_t i = 0; i < len; i++) {
    acc = (((acc << 5) | (acc >> 27)) + words[i]) ^ 0x9E3779B9u;
  }
  return acc;
}
```
<!-- /listing -->
<!-- listing asm:ay_checksum:x86_64 -->
```asm
ay_checksum:
	push	rbp
	mov	rbp, rsp
	test	rsi, rsi
	je	.LBB0_1
	mov	ecx, esi
	and	ecx, 3
	cmp	rsi, 4
	jae	.LBB0_8
	mov	eax, -2128831035
	xor	edx, edx
	jmp	.LBB0_5
.LBB0_1:
	mov	eax, -2128831035
	pop	rbp
	ret
.LBB0_8:
	and	rsi, -4
	mov	eax, -2128831035
	xor	edx, edx
.LBB0_9:
	rol	eax, 5
	add	eax, dword ptr [rdi + 4*rdx]
	xor	eax, -1640531527
	rol	eax, 5
	add	eax, dword ptr [rdi + 4*rdx + 4]
	xor	eax, -1640531527
	rol	eax, 5
	add	eax, dword ptr [rdi + 4*rdx + 8]
	xor	eax, -1640531527
	rol	eax, 5
	add	eax, dword ptr [rdi + 4*rdx + 12]
	xor	eax, -1640531527
	add	rdx, 4
	cmp	rsi, rdx
	jne	.LBB0_9
	test	rcx, rcx
	je	.LBB0_7
.LBB0_5:
	lea	rdx, [rdi + 4*rdx]
	xor	esi, esi
.LBB0_6:
	rol	eax, 5
	add	eax, dword ptr [rdx + 4*rsi]
	xor	eax, -1640531527
	inc	rsi
	cmp	rcx, rsi
	jne	.LBB0_6
.LBB0_7:
	pop	rbp
	ret
```
<!-- /listing -->

`(acc << 5) | (acc >> 27)` is recognised as a rotate and becomes one instruction, `rol eax, 5` (`c1 c0 05`): x86 has a native rotate by immediate. The 32-bit operations (`add eax, ...`, `xor eax, imm32`) zero-extend into `rax` and keep the arithmetic modulo 2^32 for free. The compiler **unrolled the loop four times**: the `.LBB0_9` body repeats `rol / add / xor` four times per iteration (`[rdi + 4*rdx]` to `[rdi + 4*rdx + 12]`), with `add rdx, 4` / `cmp rsi, rdx` as loop control, and a scalar remainder loop (`.LBB0_6`) handles `len % 4` elements (`and ecx, 3`; `cmp rsi, 4` / `jae` skips the unrolled loop for short inputs). Unrolling is a cost-model decision per target: the AArch64 and RISC-V builds of the same function (chapters 3 and 4) are not unrolled.

### `ay_try_acquire`: `lock cmpxchg`

<!-- listing c:corelib/src/sync.c#ay_try_acquire -->
```c
/// Take the lock word 0 -> 1; true when this caller now holds it.
AY_API uint32_t ay_try_acquire(uint32_t *flag) {
  uint32_t expected = 0;
  return atomic_compare_exchange_strong_explicit((_Atomic uint32_t *)flag, &expected, 1u, memory_order_acquire,
                                                 memory_order_relaxed);
}
```
<!-- /listing -->
<!-- listing asm:ay_try_acquire:x86_64 -->
```asm
ay_try_acquire:
	push	rbp
	mov	rbp, rsp
	mov	edx, 1
	xor	ecx, ecx
	xor	eax, eax
	lock		cmpxchg	dword ptr [rdi], edx
	sete	cl
	mov	eax, ecx
	pop	rbp
	ret
```
<!-- /listing -->

`atomic_compare_exchange_strong_explicit(..., 0 -> 1, memory_order_acquire, memory_order_relaxed)` is a single atomic instruction. `cmpxchg [rdi], edx` compares `eax` (the expected value, 0, cleared by the `xor eax, eax`) with the memory word; if equal it stores `edx` (1) and sets ZF, otherwise it loads the memory value into `eax` and clears ZF. The `lock` prefix makes the read-modify-write atomic across cores. `sete cl` then turns ZF into the boolean; the `xor ecx, ecx` before the `lock cmpxchg` is again a flags-before-use arrangement. x86 has a strong memory model and locked instructions are totally ordered and act as full barriers (Intel SDM vol. 3, memory ordering), so the acquire ordering needs no extra instruction.

## The real boot of the corelib image

`corelib/arch/x86_64` (`boot.s`, `kmain.c`, `linker.ld`) builds a bare-metal image: no operating system, no bootloader of its own. It runs on QEMU (`-kernel`), Xen, Firecracker and Cloud Hypervisor through the **PVH boot protocol**.

### Entry: the PVH note

A PVH loader finds the 32-bit entry point in an ELF note of type `XEN_ELFNOTE_PHYS32_ENTRY` (18). The Xen specification ([xen docs/misc/pvh.pandoc](https://github.com/xen-project/xen/blob/master/docs/misc/pvh.pandoc), read 2026-11-17) fixes the state at the jump: `ebx` points to the boot-info structure, `cr0` has only PE set (protected mode, **paging off**), `cr4` is zero, `cs`, `ds`, `es`, `ss` are flat 32-bit segments, `eflags` has IF clear (interrupts off), and the OS must set up its own stack, GDT and IDT.

<!-- listing file:corelib/arch/x86_64/boot.s#1-13 -->
```asm
# Entry from the hypervisor to C: PVH start in 32-bit protected mode, then long mode, then kmain.
# The PVH ELF note tells the loader where to jump (XEN_ELFNOTE_PHYS32_ENTRY = 18). On entry the CPU is
# in 32-bit protected mode with flat segments, paging off, interrupts off, EBX = hvm_start_info.
# We identity-map the first 1 GiB with 2 MiB pages, switch to long mode and call kmain.
    .intel_syntax noprefix

    .pushsection .note.Xen, "a", @note
    .balign 4
    .long 4, 4, 18
    .asciz "Xen"
    .balign 4
    .long _start32
    .popsection
```
<!-- /listing -->

The linker script places the note in a `PT_NOTE` segment and `.text.boot` at the start of the image at 1 MiB:

<!-- listing file:corelib/arch/x86_64/linker.ld -->
```text
/* Flat image at 1 MiB. QEMU's PVH loader reads the PT_NOTE segment to find the 32-bit entry point. */
ENTRY(_start32)

PHDRS
{
    text   PT_LOAD FLAGS(5);
    rodata PT_LOAD FLAGS(4);
    data   PT_LOAD FLAGS(6);
    note   PT_NOTE FLAGS(4);
}

SECTIONS
{
    . = 1M;
    .text : { *(.text.boot) *(.text .text.*) } :text

    . = ALIGN(4K);
    .rodata : { *(.rodata .rodata.*) } :rodata
    .note : { KEEP(*(.note.Xen)) } :rodata :note

    . = ALIGN(4K);
    .data : { *(.data .data.*) } :data
    .bss : { *(.bss .bss.*) *(COMMON) } :data

    /DISCARD/ : { *(.eh_frame .eh_frame_hdr .comment) }
}
```
<!-- /listing -->

`readelf` on the linked image (<build-host>) confirms it: entry point `0x100000`, a `NOTE` program header, and `Xen  0x00000004  Unknown note type: (0x00000012)  description data: 00 00 10 00`, that is type 18 and the entry address `0x00100000` in little endian.

### Step 1: a stack and the first two levels of page tables (still 32-bit)

<!-- listing file:corelib/arch/x86_64/boot.s#15-27 -->
```asm
    .section .text.boot, "ax", @progbits
    .code32
    .global _start32
_start32:
    cli
    mov esp, offset boot_stack_top

    mov eax, offset pdpt
    or eax, 0x3                         # present | writable
    mov dword ptr [pml4], eax
    mov eax, offset pd
    or eax, 0x3
    mov dword ptr [pdpt], eax
```
<!-- /listing -->

`.code32` makes the assembler emit 32-bit encodings. `cli` is redundant with the PVH contract but costs one byte. The page tables live in `.bss` (`pml4`, `pdpt`, `pd`, 4 KiB each, page-aligned) at physical addresses `0x103000`, `0x104000` and `0x105000` in the linked image (`nm`). They must start zeroed: `readelf -l` shows the data segment with `FileSiz 0x000000` and `MemSiz 0x013000`, so the loader has to zero-fill it, and the PVH loader of QEMU does. The first PML4 entry points to the PDPT and the first PDPT entry to the page directory; `| 0x3` sets bit 0 (present) and bit 1 (writable).

### Step 2: 512 entries of 2 MiB pages

<!-- listing file:corelib/arch/x86_64/boot.s#29-37 -->
```asm
    xor ecx, ecx                        # fill the page directory: 512 entries x 2 MiB
1:  mov eax, ecx
    shl eax, 21
    or eax, 0x83                        # present | writable | page size (2 MiB)
    mov dword ptr [pd + ecx*8], eax
    mov dword ptr [pd + ecx*8 + 4], 0
    inc ecx
    cmp ecx, 512
    jne 1b
```
<!-- /listing -->

4-level paging splits a 48-bit virtual address into four 9-bit indexes (PML4, PDPT, PD, PT) and a 12-bit offset. A page-directory entry with the **PS bit** (bit 7) set maps a 2 MiB page directly and skips the PT level, so the offset becomes 21 bits. Entry `i` maps physical `i << 21` (`shl eax, 21`) with flags `0x83` = present | writable | PS. 512 entries x 2 MiB = 1 GiB, identity-mapped (virtual = physical), enough for the image at 1 MiB, its stack and the legacy devices below 1 GiB; one PDPT entry covers 1 GiB and one PML4 entry 512 GiB. The two stores per entry write the low and high 32 bits because a page-table entry is 64 bits wide and this code still runs in 32-bit mode. Actual encodings of this loop, `objdump -d -m i386 -M intel` on the image:

```text
  100022:	89 c8                	mov    eax,ecx
  100024:	c1 e0 15             	shl    eax,0x15
  100027:	0d 83 00 00 00       	or     eax,0x83
  10002c:	89 04 cd 00 50 10 00 	mov    DWORD PTR [ecx*8+0x105000],eax
  100033:	c7 04 cd 04 50 10 00 	mov    DWORD PTR [ecx*8+0x105004],0x0
  10003a:	00 00 00 00 
  10003e:	41                   	inc    ecx
  10003f:	81 f9 00 02 00 00    	cmp    ecx,0x200
  100045:	75 db                	jne    100022 <_start32+0x22>
```

The table and stack addresses are absolute 32-bit immediates, which is why the image is built with `-fno-pic -fno-pie -mcmodel=small -static` (`tools/corelib.ts`).

### Step 3: CR3, CR4.PAE, EFER.LME, CR0.PG

<!-- listing file:corelib/arch/x86_64/boot.s#39-50 -->
```asm
    mov eax, offset pml4
    mov cr3, eax
    mov eax, cr4
    or eax, 1 << 5                      # CR4.PAE
    mov cr4, eax
    mov ecx, 0xC0000080                 # IA32_EFER
    rdmsr
    or eax, 1 << 8                      # EFER.LME
    wrmsr
    mov eax, cr0
    or eax, 1 << 31                     # CR0.PG: long mode becomes active (compatibility sub-mode)
    mov cr0, eax
```
<!-- /listing -->

The order matters. `cr3` receives the PML4 address first. **PAE** (CR4 bit 5) is mandatory for long mode: the 64-bit page-table format needs it. **LME** (EFER bit 8) is set with `rdmsr`/`wrmsr` (`ecx` = MSR number `0xC0000080`, value in `edx:eax`; only `eax` is modified because bit 8 lives in the low half). Setting **PG** (CR0 bit 31) with LME already set makes the CPU activate long mode: EFER.LMA (bit 10) becomes 1 and the CPU is in **compatibility mode**, executing 32-bit code under long-mode paging. The program counter survives because the low 1 GiB is identity-mapped, which is the reason for Step 2.

### Step 4: GDT and the far jump into 64-bit code

<!-- listing file:corelib/arch/x86_64/boot.s#72-81 -->
```asm
    .section .rodata.boot, "a", @progbits
    .balign 8
gdt:
    .quad 0x0000000000000000            # null
    .quad 0x00209A0000000000            # 0x08 code: L=1, present, executable
    .quad 0x0000920000000000            # 0x10 data: present, writable
gdt_end:
gdt_ptr:
    .word gdt_end - gdt - 1
    .long gdt
```
<!-- /listing -->

A descriptor is 8 bytes. `0x00209A0000000000`: access byte `0x9A` (present, ring 0, code/data segment, executable, readable) and flags nibble `0x2` = **L bit** (64-bit code, D must be 0). `0x0000920000000000`: access `0x92` (present, ring 0, data, writable). Base and limit are zero because 64-bit mode ignores them. `gdt_ptr` is the 6-byte operand of `lgdt`: a 16-bit limit (`gdt_end - gdt - 1`) and a 32-bit base.

<!-- listing file:corelib/arch/x86_64/boot.s#52-55 -->
```asm
    lgdt [gdt_ptr]
    .byte 0xEA                          # ljmp 0x08:long_mode, spelled as bytes: far jump into the 64-bit code segment
    .long long_mode
    .word 0x08
```
<!-- /listing -->

In compatibility mode only a **far jump** can load `cs` with the L-bit descriptor and so enter true 64-bit mode. The source spells it as bytes: `0xEA` is `jmp ptr16:32`, followed by the 32-bit offset and the 16-bit selector `0x08` (descriptor index 1, RPL 0). The linked bytes are `ea 7f 00 10 00 08 00`, which `objdump -m i386` decodes as `jmp 0x8:0x10007f`.

### Step 5: 64-bit code, data segments, stack, `kmain`

<!-- listing file:corelib/arch/x86_64/boot.s#57-70 -->
```asm
    .code64
long_mode:
    mov ax, 0x10
    mov ds, ax
    mov es, ax
    mov ss, ax
    xor eax, eax
    mov fs, ax
    mov gs, ax
    mov rsp, offset boot_stack_top
    xor ebp, ebp
    call kmain
2:  hlt
    jmp 2b
```
<!-- /listing -->

`.code64` switches the assembler back. The data selectors (`0x10`) are loaded into `ds es ss`; `fs` and `gs` get the null selector. `mov rsp, offset boot_stack_top` assembles to `48 c7 c4 00 60 11 00`, the sign-extended `mov r/m64, imm32` form: a 32-bit absolute address is enough because the image sits at 1 MiB. `xor ebp, ebp` ends the frame-pointer chain for unwinders, and `call kmain` follows the System V ABI: `rsp` is `0x116000` (16-byte aligned), the `call` pushes 8 bytes. The stack is 64 KiB in `.bss`:

<!-- listing file:corelib/arch/x86_64/boot.s#83-89 -->
```asm
    .section .bss.boot, "aw", @nobits
    .balign 4096
pml4:           .skip 4096
pdpt:           .skip 4096
pd:             .skip 4096
boot_stack:     .skip 65536
boot_stack_top:
```
<!-- /listing -->

### C takes over

<!-- listing file:corelib/arch/x86_64/kmain.c#35-41 -->
```c
/// Run the shared demo on COM1 and tell QEMU the verdict through isa-debug-exit: status (code << 1) | 1,
/// so 0x10 gives 33 (pass) and 0x11 gives 35 (fail). On real hardware the write does nothing and we halt.
[[noreturn]] void kmain(void) {
  serial_init();
  const ay_console com1 = {serial_put, nullptr};
  outb(DEBUG_EXIT, ay_run_reference(&com1) ? 0x10 : 0x11);
  halt();
```
<!-- /listing -->

`kmain` is ordinary C23 (`[[noreturn]]`, `nullptr`): initialise the UART, build the `ay_console` descriptor (a function pointer and a context pointer, kept on the stack: the `sub rsp, 0x10` in the disassembly), run the shared reference demo `ay_run_reference`, write the verdict to the exit device and halt. It is compiled with the same `-ffreestanding -mgeneral-regs-only -mno-red-zone` flags as the listings, and linked against nothing: `libc.c` in `corelib/src` provides the few functions the demo needs.

### Serial output: the 16550 UART with `in` and `out`

x86 has a separate 64 Ki **I/O port** address space, reached with `in` and `out` (privileged unless the I/O permission bitmap allows it). The first serial port, COM1, sits at port `0x3F8`.

<!-- listing file:corelib/arch/x86_64/kmain.c#4-12 -->
```c
enum : uint16_t { COM1 = 0x3F8, DEBUG_EXIT = 0xF4 };

static void outb(uint16_t port, uint8_t value) { __asm__ volatile("outb %0, %1" : : "a"(value), "Nd"(port)); }

static uint8_t inb(uint16_t port) {
  uint8_t value;
  __asm__ volatile("inb %1, %0" : "=a"(value) : "Nd"(port));
  return value;
}
```
<!-- /listing -->

`out dx, al` writes `al` to the port in `dx` (`ee`, one byte); `in al, dx` reads (`ec`). The port must be in `dx`, or an 8-bit immediate for ports below 256. The GNU inline-assembly constraints say exactly that: `"a"(value)` puts the byte in `al`, `"Nd"(port)` allows an 8-bit constant or `dx`. Observed in the linked image: `serial_init` compiles to `xor eax, eax / mov dx, 0x3f9 / out dx, al` and so on, `serial_put` to `mov dx, 0x3fd / in al, dx / test al, 0x20 / je` and `mov dx, 0x3f8 / out dx, al`, and `kmain` writes the exit device with the immediate form `out 0xf4, al` because `0xf4` is a constant below 256. The statements are `__asm__ volatile` so the compiler may neither delete nor reorder them.

<!-- listing file:corelib/arch/x86_64/kmain.c#14-23 -->
```c
/// 115200 baud, 8 data bits, no parity, one stop bit, FIFO on.
static void serial_init(void) {
  outb(COM1 + 1, 0x00); // interrupts off
  outb(COM1 + 3, 0x80); // DLAB on
  outb(COM1, 0x01);     // divisor 1 = 115200 baud
  outb(COM1 + 1, 0x00);
  outb(COM1 + 3, 0x03); // 8N1, DLAB off
  outb(COM1 + 2, 0xC7); // enable and clear FIFOs
  outb(COM1 + 4, 0x0B); // DTR, RTS, OUT2
}
```
<!-- /listing -->

The 16550 register file is eight registers at `base + 0..7`; two of them share an address with the baud-rate divisor while **DLAB** (line-control bit 7, `0x80`) is set. The sequence is: interrupts off (`+1` = 0), DLAB on (`+3` = `0x80`), divisor 1 in `+0`/`+1` (115200 baud divided by 1), `+3` = `0x03` for 8 data bits, no parity, one stop bit with DLAB off, `+2` = `0xC7` to enable and clear the FIFOs, `+4` = `0x0B` for DTR, RTS and OUT2 (on PC-compatible hardware OUT2 gates the UART interrupt line). Register meanings: Linux `include/uapi/linux/serial_reg.h` (`UART_LCR_DLAB` `0x80`, `UART_LSR` = 5, `UART_LSR_THRE` `0x20`).

<!-- listing file:corelib/arch/x86_64/kmain.c#25-29 -->
```c
static void serial_put(void *, uint8_t byte) {
  while (!(inb(COM1 + 5) & 0x20)) {
  }
  outb(COM1, byte);
}
```
<!-- /listing -->

Sending a byte is polling: read the line status register (`+5`) until bit 5 (**THRE**, transmit holding register empty) is set, then write the byte to `+0`.

### Telling QEMU the verdict: `isa-debug-exit`

<!-- listing file:corelib/arch/x86_64/kmain.c#35-36 -->
```c
/// Run the shared demo on COM1 and tell QEMU the verdict through isa-debug-exit: status (code << 1) | 1,
/// so 0x10 gives 33 (pass) and 0x11 gives 35 (fail). On real hardware the write does nothing and we halt.
```
<!-- /listing -->

QEMU's `isa-debug-exit` device is a port that terminates the VM when written; the process exit status is `(value << 1) | 1` (QEMU `hw/misc/debugexit.c`: `exit((val << 1) | 1)`). The image writes `0x10` on success, giving status 33, and `0x11` on failure, giving 35. The device must be placed where the code expects it, `-device isa-debug-exit,iobase=0xf4,iosize=0x04`; the default `iobase` of the device is `0x501`.
