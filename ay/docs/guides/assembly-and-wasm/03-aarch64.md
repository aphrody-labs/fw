# 3. AArch64: registers, AAPCS64, Linux syscalls, a bare-metal boot

AArch64 is the 64-bit execution state of Arm's A-profile architecture (Armv8-A and later). It is a load/store RISC: **every instruction is 4 bytes**, arithmetic works on registers, memory is reached only through load and store instructions, and a three-operand form (`add x0, x1, x2`) is the norm. Everything below was assembled with GNU binutils 2.47 and run on `<build-host>` with QEMU 11.0.3 on 2026-11-17, or generated by clang 23 from the C corelib (`corelib/src`, `--target=aarch64-none-elf -O2`, baseline Armv8.0 without the LSE atomics).

## Registers

| Name | Meaning |
|---|---|
| `x0`-`x30` | 31 general-purpose 64-bit registers |
| `w0`-`w30` | the low 32 bits of `x0`-`x30`; writing a `w` register **zero-extends** into the `x` register |
| `sp` | the stack pointer, a separate register per exception level (`SP_EL0`, `SP_EL1`...); a load or store through `sp` requires 16-byte alignment |
| `xzr` / `wzr` | reads as zero, writes are discarded. In the instruction encoding it shares register number 31 with `sp`; each instruction defines which of the two number 31 means (`add` and `sub` without flags use `sp`, `bics`, `subs`, `cmp` use `xzr`) |
| `pc` | not a general register: it cannot be named as an operand. Branches, `adr`, `adrp` and literal loads use it implicitly |
| `x30` = `lr` | the link register: `bl` stores the return address there, `ret` jumps to it |
| `x29` = `fp` | the frame pointer by convention |
| `v0`-`v31` | 128-bit SIMD and floating-point registers (`b`, `h`, `s`, `d`, `q` views) |
| `NZCV` | the condition flags: **N** negative, **Z** zero, **C** carry (set means no borrow after a subtract), **V** overflow. Written by `adds`, `subs`, `cmp`, `tst`, `ands`, `bics` and friends; the plain forms leave them alone |
| System registers | read with `mrs xN, NAME`, written with `msr NAME, xN`. Examples used below: `CurrentEL`, `VBAR_EL1`, `ESR_EL1`, `ELR_EL1`; the MMU lives in `SCTLR_EL1`, `TTBR0_EL1`, `TCR_EL1`, `MAIR_EL1` |

Immediates are small: a 32-bit constant does not fit in a 4-byte instruction, so it is built with `movz`/`movk` (16 bits at a time). The checksum constant `0x811C9DC5` becomes `mov w8, #40389` (`0x9DC5`) and `movk w8, #33052, lsl #16` (`0x811C`) in the listing below. Arithmetic immediates are 12 bits (optionally shifted by 12), and logical immediates are **bit patterns** (runs of ones, rotated, replicated) rather than arbitrary values, which is why the compiler keeps the `0x9E3779B9` constant in a register (`w10`) for the loop instead of writing `eor w8, w8, #imm`.

## Exception levels

AArch64 has four privilege levels, **EL0** to **EL3**, a higher number being more privileged:

| Level | Typical software |
|---|---|
| EL0 | applications |
| EL1 | operating system kernel |
| EL2 | hypervisor |
| EL3 | secure monitor / firmware |

An exception (`svc`, interrupt, fault) moves execution to the same or a higher level, saving the return address in `ELR_ELx`, the processor state in `SPSR_ELx` and the cause in `ESR_ELx`; `eret` returns. The reset level is the highest implemented one and firmware drops to a lower level before starting the next stage. Observed on QEMU: the same image prints `EL1` when started with `-M virt` and `EL2` with `-M virt,virtualization=on`.

## AAPCS64, the calling convention

From the Arm ABI document ([aapcs64.rst](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst), read 2026-11-17):

| Register | Role |
|---|---|
| `x0`-`x7` | arguments and results (caller-saved) |
| `x8` | **indirect result location**: when the result is too large for registers, the caller passes the address of the result block in `x8` |
| `x9`-`x15` | caller-saved temporaries |
| `x16`, `x17` (IP0, IP1) | scratch for linker veneers and PLT code, otherwise caller-saved |
| `x18` | the platform register, reserved or caller-saved depending on the OS |
| `x19`-`x28` | **callee-saved** |
| `x29` (FP) | frame pointer; the ABI wants a linked list of 16-byte frame records |
| `x30` (LR) | link register |
| `sp` | must satisfy `SP mod 16 = 0` at public interfaces |

The conventional prologue and epilogue save the pair `x29, x30` with one instruction, as in the boot example below:

```asm
puts:
	stp	x29, x30, [sp, #-16]!	// pre-index: sp -= 16, then store the pair
	mov	x29, sp			// new frame record
	...
	ldp	x29, x30, [sp], #16	// load the pair, then sp += 16 (post-index)
	ret
```

The five functions of the corelib are leaf functions that use only `x0`-`x10` and return in `w0`, so they need no frame and clang emits no frame-pointer prologue for them (unlike on x86-64, chapter 2).

## Loads, stores and addressing

`ldr`, `str` (and `ldrb`, `ldrh`, `ldrsw`...) move data; `ldp` and `stp` move **two registers at once**. The addressing modes seen in this chapter:

| Form | Meaning | Where |
|---|---|---|
| `[x0]`, `[x0, #8]` | base plus unsigned scaled or signed unscaled immediate | `ldr w10, [x9, #0x18]` in `putc` |
| `[x0, x1, lsl #2]`, `[x9, w8, uxtw]` | base plus register, optionally extended and shifted | `ldrb w0, [x9, w8, uxtw]` in `ay_arg_count` |
| `[x0, #-16]!` | **pre-index**: update the base first, then access | `stp x29, x30, [sp, #-16]!` |
| `[x0], #4` | **post-index**: access, then update the base | `ldr w11, [x0], #4` in `ay_checksum` |
| `adrp x9, sym` + `add x9, x9, :lo12:sym` | the 4 KiB page of a symbol (PC-relative, +-4 GiB), then its low 12 bits | `ay_arg_count` |
| `adr x1, sym` | a PC-relative address within +-1 MiB | the examples below |

## Conditional execution without branches

There is no predication of every instruction like in 32-bit Arm. The A64 conditionals are `b.cond`, and the **conditional select family** that picks between two registers on the flags: `csel`, `csinc`, `csinv`, `csneg`, and the aliases `cset` (set to 1 if the condition holds, else 0) and `csetm`. Condition codes: `eq ne` (Z), `hs lo` (C: unsigned higher-or-same, lower; `cs`/`cc` are the same codes), `hi ls` (unsigned), `ge lt gt le` (signed), `mi pl vs vc`. `cmp x, y` is `subs xzr, x, y`; `tst` is `ands xzr, ...`.

## Linux syscalls

| Item | Register |
|---|---|
| Instruction | `svc #0` |
| Syscall number | `x8` (`write` = 64, `exit_group` = 94, the generic table in `include/uapi/asm-generic/unistd.h`) |
| Arguments | `x0`-`x5` |
| Result | `x0` |

([syscall(2)](https://man7.org/linux/man-pages/man2/syscall.2.html) row arm64: `svc #0`, number in `w8`, result in `x0`; read 2026-11-17.)

### A complete program, no libc

<!-- listing file:corelib/asm/hello_linux_aarch64.s -->
```asm
// Linux AArch64 user space, no libc: write(1, msg, len); exit_group(0).
// Syscall ABI: number in x8, arguments in x0..x5, `svc #0` traps to EL1, result in x0.
// Build: aarch64-linux-gnu-as hello_linux_aarch64.s -o hello.o && aarch64-linux-gnu-ld hello.o -o hello
	.globl	_start

	.section .rodata
msg:	.ascii	"hello from AArch64\n"
	.set	msg_len, . - msg

	.text
_start:
	mov	x0, #1			// fd 1 = stdout
	adr	x1, msg			// buffer, PC-relative (+-1 MiB)
	mov	x2, #msg_len		// byte count
	mov	x8, #64			// __NR_write
	svc	#0
	mov	x0, #0			// status 0
	mov	x8, #94			// __NR_exit_group
	svc	#0
```
<!-- /listing -->

`<build-host>` is an x86-64 machine, so the AArch64 binary runs under `qemu-aarch64` (user-mode emulation, which translates the guest `svc #0` into the host syscall). Observed on <build-host>, 2026-11-17:

```text

$ file hello

$ qemu-aarch64 ./hello; echo "exit=$?"

```

Disassembly of the result (`aarch64-linux-gnu-objdump -d`), eight 4-byte instructions at consecutive addresses:

```text
  400078:	d2800020 	mov	x0, #0x1                   	// #1
  40007c:	100000e1 	adr	x1, 400098 <msg>
  400080:	d2800262 	mov	x2, #0x13                  	// #19
  400084:	d2800808 	mov	x8, #0x40                  	// #64
  400088:	d4000001 	svc	#0x0
  40008c:	d2800000 	mov	x0, #0x0                   	// #0
  400090:	d2800bc8 	mov	x8, #0x5e                  	// #94
  400094:	d4000001 	svc	#0x0
```

`mov x0, #1` is the alias of `movz x0, #1`; `adr` holds a 21-bit PC-relative offset (here `+0x1c`), which is why it can only reach +-1 MiB.

## The same functions, compiled

Regenerated by `bun tools/listings.ts` from `corelib/src` with `clang -S -O2 -std=c23 -ffreestanding --target=aarch64-none-elf` (flags in `tools/corelib.ts`). Labels such as `.LBB0_2` are compiler-internal.

### `ay_rights_allow`: `bics` and `cset`

<!-- listing c:corelib/src/abi.c#ay_rights_allow -->
```c
/// Whether a capability holding `have` may perform an operation that needs `need`.
AY_API uint32_t ay_rights_allow(uint32_t have, uint32_t need) { return (have & need) == need; }
```
<!-- /listing -->
<!-- listing asm:ay_rights_allow:aarch64 -->
```asm
ay_rights_allow:
	bics	wzr, w1, w0
	cset	w0, eq
	ret
```
<!-- /listing -->

`have & need == need` is `need & !have == 0`. `bics wzr, w1, w0` is "bit clear and set flags": it computes `w1 & ~w0` (that is `need & ~have`), discards the value into `wzr` and keeps only the flags; `cset w0, eq` turns Z into 0 or 1. AArch64 has `bic` (AND NOT) as a real instruction, so the inversion that x86 does with `not` is folded in. Arguments arrive in `w0`, `w1`, the result leaves in `w0`: three instructions.

### `ay_first_free`: `rbit` + `clz`

<!-- listing c:corelib/src/mem.c#ay_first_free -->
```c
/// Index of the lowest clear bit, or -1 when all 64 are set: the first free frame.
AY_API int32_t ay_first_free(uint64_t bits) {
  if (!~bits) return -1;
  return __builtin_ctzll(~bits);
}
```
<!-- /listing -->
<!-- listing asm:ay_first_free:aarch64 -->
```asm
ay_first_free:
	mvn	x8, x0
	cmn	x0, #1
	rbit	x8, x8
	clz	x8, x8
	csinv	w0, w8, wzr, ne
	ret
```
<!-- /listing -->

Base AArch64 has `clz` (count leading zeros) but no count-trailing-zeros, so `__builtin_ctzll(~bits)` is `mvn` (invert) followed by `rbit` (reverse the bit order) and `clz`. The source tests the full-bitmap case first, and `cmn x0, #1` is that test: it adds 1 to the original bitmap and sets Z when the sum is zero, i.e. when all 64 bits were set (`cmn` is `adds xzr, ...`, an add that keeps only the flags). `csinv w0, w8, wzr, ne` then returns `w8` when Z is clear and `~wzr` = -1 otherwise. The compare, the select and the inversion are one instruction, so there is no branch. The flags set by `cmn` survive until `csinv` because `rbit` and `clz` do not write them, which is why the scheduler may place `cmn` before them.

### `ay_arg_count`: byte table with `adrp`

<!-- listing c:corelib/src/abi.c#ay_arg_count -->
```c
/// Number of arguments each syscall reads (0 for an unknown number).
AY_API uint32_t ay_arg_count(uint32_t nr) {
  switch (nr) {
  case AY_SYS_VERSION:
  case AY_SYS_YIELD:
  case AY_SYS_FRAME_ALLOC:
    return 0;
  case AY_SYS_CAP_DROP:
  case AY_SYS_SEND:
  case AY_SYS_RECV:
  case AY_SYS_MSG_GET:
  case AY_SYS_FRAME_FREE:
    return 1;
  case AY_SYS_MSG_SET:
  case AY_SYS_CAP_DERIVE:
    return 2;
  case AY_SYS_LOG:
    return 3;
  default:
    return 0;
  }
}
```
<!-- /listing -->
<!-- listing asm:ay_arg_count:aarch64 -->
```asm
ay_arg_count:
	sub	w8, w0, #2
	cmp	w8, #8
	b.hi	.LBB2_2
	adrp	x9, .Lswitch.table.ay_arg_count
	add	x9, x9, :lo12:.Lswitch.table.ay_arg_count
	ldrb	w0, [x9, w8, uxtw]
	ret
.LBB2_2:
	mov	w0, wzr
	ret
.Lswitch.table.ay_arg_count:
	.ascii	"\003\002\001\001\001\002\001\000\001"
```
<!-- /listing -->

Same transformation as on x86-64: a dense `switch` becomes a nine-byte table indexed by `number - 2` (`sub w8, w0, #2`), guarded by one unsigned range check (`cmp w8, #8` / `b.hi`, which also catches 0 and 1 because the subtraction wraps). The address of the table is built with the `adrp` / `add :lo12:` pair, the A64 way to reach any symbol in two instructions without a literal pool, and the byte is loaded with an extended register offset `[x9, w8, uxtw]` (zero-extend the 32-bit index). The default 0 is a separate `mov w0, wzr` on the out-of-range path.

### `ay_checksum`: `ror`, post-index loads

<!-- listing c:corelib/src/ipc.c#ay_checksum -->
```c
/// Rotate-and-add checksum of a message; the loop shows how each ISA spells a rotate.
AY_API uint32_t ay_checksum(const uint32_t *words, size_t len) {
  uint32_t acc = 0x811C9DC5u;
  for (size_t i = 0; i < len; i++) {
    acc = (((acc << 5) | (acc >> 27)) + words[i]) ^ 0x9E3779B9u;
  }
  return acc;
}
```
<!-- /listing -->
<!-- listing asm:ay_checksum:aarch64 -->
```asm
ay_checksum:
	mov	w8, #40389
	movk	w8, #33052, lsl #16
	cbz	x1, .LBB0_3
	mov	w9, #31161
	movk	w9, #40503, lsl #16
.LBB0_2:
	ror	w8, w8, #27
	ldr	w10, [x0], #4
	subs	x1, x1, #1
	add	w8, w10, w8
	eor	w8, w8, w9
	b.ne	.LBB0_2
.LBB0_3:
	mov	w0, w8
	ret
```
<!-- /listing -->

A rotate **left** by 5 is a rotate **right** by 27 (`ror w8, w8, #27`); `ror` by an immediate is an alias of `extr w8, w8, w8, #27`, which extracts a 32-bit window from the concatenation of a register with itself. The loop is six instructions: `ldr w10, [x0], #4` loads the next word and advances the pointer in one instruction (post-index), `subs x1, x1, #1` counts the **elements** down and sets Z for the branch, `b.ne` repeats. Both 32-bit constants are built outside the loop with `mov` + `movk` and kept in `w8` (the accumulator seed) and `w9` (the xor mask; a logical immediate cannot encode `0x9E3779B9`). The compiler did not unroll this loop on AArch64 (it did on x86-64): unrolling is decided per target by LLVM's cost model.

### `ay_try_acquire`: load-exclusive / store-exclusive

<!-- listing c:corelib/src/sync.c#ay_try_acquire -->
```c
/// Take the lock word 0 -> 1; true when this caller now holds it.
AY_API uint32_t ay_try_acquire(uint32_t *flag) {
  uint32_t expected = 0;
  return atomic_compare_exchange_strong_explicit((_Atomic uint32_t *)flag, &expected, 1u, memory_order_acquire,
                                                 memory_order_relaxed);
}
```
<!-- /listing -->
<!-- listing asm:ay_try_acquire:aarch64 -->
```asm
ay_try_acquire:
.LBB0_1:
	ldaxr	w8, [x0]
	cbnz	w8, .LBB0_4
	mov	w8, #1
	stxr	w9, w8, [x0]
	cbnz	w9, .LBB0_1
	mov	w0, w8
	ret
.LBB0_4:
	mov	w8, wzr
	clrex
	mov	w0, w8
	ret
```
<!-- /listing -->

Armv8.0 has no single compare-and-swap instruction. It builds atomics from a **load-exclusive / store-exclusive** pair: `ldaxr w8, [x0]` loads with **acquire** semantics and arms the *exclusive monitor* for that address; `cbnz w8, ...` leaves if the lock is already taken; `stxr w9, w8, [x0]` stores 1 only if the monitor is still armed and writes its status to `w9` (0 = stored, 1 = lost the reservation, for example after an interrupt or a store by another core), and `cbnz w9, .LBB0_1` retries. On the failure path `clrex` drops the monitor so that it does not stay armed. This is the *LL/SC* style, also used by RISC-V (chapter 4).

Armv8.1 added the **LSE** atomics, among them `cas`. With `-march=armv8.1-a` the same function compiles to a single instruction (observed with clang 23.1.5, not part of the generated listings):

```asm
ay_try_acquire:
	mov	w8, wzr
	mov	w9, #1
	casa	w8, w9, [x0]		// compare-and-swap, acquire: w8 = expected 0, w9 = new 1, old value returned in w8
	cmp	w8, #0
	cset	w0, eq
	ret
```

## Booting AArch64 on QEMU `virt`

On the `virt` board, [QEMU's source](https://github.com/qemu/qemu/blob/master/hw/arm/virt.c) (`virt_memmap`, read 2026-11-17) puts flash at 0, the **PL011 UART0 at `0x09000000`** and RAM from `0x40000000` (1 GiB). With `-kernel image.elf` QEMU loads the ELF at its link address and jumps to the entry point at EL1; `-M virt,virtualization=on` starts at EL2 instead. The boot environment at the start is minimal: MMU off, no stack, no vectors, interrupts masked. A kernel therefore does, in this order:

1. **Stack.** Point `sp` at reserved memory (`.bss` in the example).
2. **Vector table.** Write the address of a 2 KiB-aligned table to `VBAR_EL1` (`VBAR_EL2` when running at EL2). The table has 16 entries of 0x80 bytes (32 instructions each): four groups, each with synchronous, IRQ, FIQ and SError entries. The groups are "current EL with SP0" (offset `0x000`), "current EL with SPx" (`0x200`), "lower EL using AArch64" (`0x400`) and "lower EL using AArch32" (`0x600`). A kernel taking an exception from its own EL1 with `SP_EL1` lands at `0x200`.
3. **Devices.** The PL011 data register is at offset `0x00`, the flag register `UARTFR` at `0x18`; bit 5 is **TXFF**, transmit FIFO full (`PL011_FLAG_TXFF 0x20` in QEMU's `hw/char/pl011.c`). The code polls it and writes bytes. QEMU's PL011 needs no baud-rate setup.
4. **MMU (not demonstrated here).** To turn on virtual memory a kernel fills translation tables, programs `MAIR_EL1` (memory attribute types), `TCR_EL1` (granule size and address-range) and `TTBR0_EL1`/`TTBR1_EL1` (table roots), then sets `SCTLR_EL1.M` (bit 0) followed by an `isb`. The Linux arm64 boot protocol requires the MMU off at entry ([kernel.org booting](https://www.kernel.org/doc/html/latest/arch/arm64/booting.html)). The example stays with the MMU off, where every address is physical.

The example below does steps 1 to 3, takes one real exception on purpose, and exits through Arm semihosting.

<!-- listing file:corelib/asm/boot_virt_aarch64.s -->
```asm
// Bare-metal AArch64 for QEMU `-M virt`: EL1 entry, stack, vector table, PL011 output, one SVC exception, semihosting exit.
// Build: aarch64-linux-gnu-as boot_virt_aarch64.s -o boot.o && aarch64-linux-gnu-ld -nostdlib -Ttext=0x40000000 boot.o -o boot.elf
// Run:   qemu-system-aarch64 -M virt -cpu cortex-a72 -nographic -semihosting -kernel boot.elf
	.equ	UART0, 0x09000000	// PL011 on the virt board
	.equ	UARTFR, 0x18		// flag register: bit 5 = TXFF (transmit FIFO full)

	.text
	.globl	_start
_start:
	adrp	x0, stack_top		// the loader gives us no stack: point SP into .bss
	add	x0, x0, :lo12:stack_top
	mov	sp, x0
	adr	x0, vectors		// 2 KiB-aligned table of 16 entries
	msr	vbar_el1, x0
	isb

	adr	x0, msg_boot
	bl	puts
	mrs	x1, CurrentEL		// bits [3:2] hold the exception level
	lsr	x1, x1, #2
	add	w0, w1, #'0'
	bl	putc
	mov	w0, #'\n'
	bl	putc

	svc	#0			// synchronous exception from EL1 to EL1: vector at VBAR + 0x200
	adr	x0, msg_back
	bl	puts

	mov	x0, #0x18		// semihosting SYS_EXIT; x1 points to {reason, exit status}
	adr	x1, exit_block
	hlt	#0xf000
1:	wfi
	b	1b

putc:					// w0 = byte; clobbers x9, w10
	mov	x9, #UART0
1:	ldr	w10, [x9, #UARTFR]
	tbnz	w10, #5, 1b		// wait while the FIFO is full
	strb	w0, [x9]
	ret

puts:					// x0 = NUL-terminated string; clobbers x9-x12
	stp	x29, x30, [sp, #-16]!
	mov	x29, sp
	mov	x12, x0
1:	ldrb	w0, [x12], #1
	cbz	w0, 2f
	bl	putc
	b	1b
2:	ldp	x29, x30, [sp], #16
	ret

sync_handler:				// ESR_EL1[31:26] is the exception class; 0x15 = SVC from AArch64
	mrs	x0, esr_el1
	lsr	x0, x0, #26
	cmp	x0, #0x15
	b.ne	hang
	adr	x0, msg_svc
	bl	puts
	eret				// back to ELR_EL1, the instruction after the svc
hang:	b	hang

	.macro	ventry target
	.balign	128			// every entry owns 0x80 bytes
	b	\target
	.endm

	.balign	2048
vectors:
	ventry	hang			// 0x000 current EL, SP0: sync
	ventry	hang			// 0x080 irq
	ventry	hang			// 0x100 fiq
	ventry	hang			// 0x180 serror
	ventry	sync_handler		// 0x200 current EL, SPx: sync  <- our SVC lands here
	ventry	hang			// 0x280 irq
	ventry	hang			// 0x300 fiq
	ventry	hang			// 0x380 serror
	.rept	8			// lower EL, AArch64 and AArch32
	ventry	hang
	.endr

	.section .rodata
msg_boot: .asciz "hello from AArch64 EL"
msg_svc:  .asciz "caught svc (ESR_EL1.EC == 0x15)\n"
msg_back: .asciz "returned from the handler, exiting\n"
	.balign	8
exit_block: .quad 0x20026, 0		// ADP_Stopped_ApplicationExit, status 0

	.bss
	.balign	16
	.skip	4096
stack_top:
```
<!-- /listing -->

How it works, instruction by instruction:

- `adrp x0, stack_top` / `add x0, x0, :lo12:stack_top` / `mov sp, x0`: build the stack address, then move it into `sp`. `mov sp, x0` is encoded as `add sp, x0, #0` (`9100001f` in the disassembly): the `orr`-based form of `mov` reads register number 31 as `xzr`, while `add` reads it as `sp`, so the assembler picks `add` whenever `sp` is involved.
- `msr vbar_el1, x0` + `isb`: install the vectors; the instruction synchronization barrier makes sure the next instruction sees the new value. The linked table is at `0x40000800`, 2 KiB aligned as required.
- `mrs x1, CurrentEL`, `lsr x1, x1, #2`: bits `[3:2]` hold the level; adding `'0'` makes it a digit.
- `svc #0` raises a synchronous exception. The CPU saves the address of the *next* instruction in `ELR_EL1`, writes `ESR_EL1`, masks interrupts and branches to `VBAR_EL1 + 0x200`. `ESR_EL1[31:26]` is the exception class; `0x15` is "SVC executed in AArch64". The handler checks it, prints, and `eret` resumes after the `svc`.
- Exit: `hlt #0xf000` with `x0 = 0x18` (`SYS_EXIT`) and `x1` pointing to a two-word block `{0x20026, status}` (`ADP_Stopped_ApplicationExit`, then the exit status) is the AArch64 **semihosting** exit ([Arm semihosting spec](https://github.com/ARM-software/abi-aa/blob/main/semihosting/semihosting.rst), read 2026-11-17). QEMU honours it only with `-semihosting`; without the flag the run never ends, observed as a timeout.

Observed on <build-host>, 2026-11-17 (QEMU 11.0.3):

```text
$ aarch64-linux-gnu-as boot_virt_aarch64.s -o boot.o
$ aarch64-linux-gnu-ld -nostdlib -Ttext=0x40000000 boot.o -o boot.elf
$ qemu-system-aarch64 -M virt -cpu cortex-a72 -nographic -semihosting -kernel boot.elf; echo "exit=$?"
hello from AArch64 EL1
caught svc (ESR_EL1.EC == 0x15)
returned from the handler, exiting
exit=0
```

Variations, also observed: with `-M virt,virtualization=on` the first line reads `hello from AArch64 EL2` (the following `svc` then goes to the unset `VBAR_EL2` and the run hangs, as expected for an image that only installed `VBAR_EL1`); with the exit block changed to `{0x20026, 7}` QEMU exits with status 7. The LLVM toolchain gives the same results (observed on <build-host>): `clang --target=aarch64-linux-gnu -c hello_linux_aarch64.s` + `ld.lld` runs under `qemu-aarch64`, and `clang --target=aarch64-none-elf -c boot_virt_aarch64.s` + `ld.lld -Ttext=0x40000000` boots to the same three lines with exit status 0. `tools/asm-examples.test.ts` rebuilds and runs both, with clang and `ld.lld` when present and GNU binutils otherwise, and checks the three lines.
