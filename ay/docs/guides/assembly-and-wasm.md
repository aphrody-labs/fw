# Coding in assembly and in WebAssembly, from one code base

A guide for the Aphrody SDK. It teaches assembly (x86-64, AArch64, RISC-V) and WebAssembly side by side, and every concept is shown on the **same function** taken from one freestanding C23 code base, `corelib/`: native assembly and WAT come out of `clang`, not out of the author's head. The listings are regenerated by `tools/listings.ts`, and CI fails when the guide drifts from the code.

Reference reading: the French Wikipedia article [Assembleur](https://fr.wikipedia.org/wiki/Assembleur), [webassembly.org](https://webassembly.org/) and the [Wasm core specification](https://www.w3.org/TR/wasm-core-2/).

A correction to a common assumption: as of this date Wasm 2.0 on w3.org is a *Candidate Recommendation Draft*, and the version that engines and webassembly.org treat as current is 3.0. The guide says which edition each feature belongs to.

## Reproduce the proofs

```sh
bun test corelib/host                             # native process (clang, clang-cl), the Wasm corelib + the hand-written WAT app under Bun
bun tools/corelib-qemu.ts --remote                # bare-metal image in QEMU on the build host, serial log vs the golden file
bun tools/corelib-component.ts --remote           # the component build on wasmtime, same transcript
bun tools/listings.ts --check                     # every listing of this guide equals what the code generates
```

The expected output every run shares is `corelib/tests/golden/boot.txt`; the QEMU serial log of the last run is `corelib/proof/qemu-boot.txt`.
