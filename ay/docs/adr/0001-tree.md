# ADR-1: Product-first tree on upstream conventions

Status: accepted, 2026-11-16.

## Context
The previous monorepo (aphrody-labs/ay, archived) split code by Android and Chromium layers: `system/`,
`frameworks/`, `device/`, `hardware/`, `kernel/`, `prebuilts/`. With no AOSP build behind it, the layers had no
meaning: 27,765 files, 275 Cargo members, about 150 Bun crates copied beside the Bun fork they duplicated, four
overlapping web apps, generated reports committed daily, and `cargo check --workspace` red on a clean checkout.

## Decision
- Products at the top (`apps/<product>`), shared Rust in a flat `crates/` (Zed: 253 crates, flat), shared Bun
  packages in `packages/` (Bun workspaces guide), the OS distribution as data in `os/`, the brand in `brand/`.
- Upstreams (AOSP through Waydroid, Chromium, Linux, the Bun fork) are consumed as submodules or fetched by their
  own tools; their directory layouts are never copied.
- `ay.toml` is the single identity source; CI and tools read names from it.

## Consequences
Adding a product means one folder in `apps/` and its crates or packages; moving code between products means moving
crates, not rewriting paths across layers. A unit is added only when it builds and has tests.
