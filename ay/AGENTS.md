# AGENTS.md

Contract for every agent working in this repository. Names come from `ay.toml`.

## Scope
- This repository is the SDK of Aphrody: C ABI, OpenAPI, docs, spec, standards, corelib, libc and the
  design system, in whatever language fits each unit (C and its derivatives, assembly, Rust, Zig,
  WebGPU, Python, .NET, Bun). LLVM first, tree-sitter, C-ABI FFI, LTO, AOT, unified lib/MSVC, cross
  arch/OS/GPU/platform (ADR-0008). The complete OS is `aphrody-labs/aphrody`; this SDK is independent of it
  and versioned on its own. Satellites (`ay.toml` [repos], [registries]) build on both.
- ay also hosts the workspace layer: `ay.toml` [repos] is the registry of the live repositories (each checked out once, side by
  side under one root), `workspace.just` holds the root recipes (the root justfile only imports it) and `tools/workspace.ts`
  implements them (status, audit, manifests, pull, run). Retired repositories stay in [retired] and are never checked out.
- The products and their definition of done are in `docs/spec.md`; the tree and toolchain in
  `docs/architecture.md` and `docs/adr/`; the full scope, row by row, in `docs/features.toml`.
- A feature is done only with a proof in the matrix (test id, screenshot path or artifact URL);
  `bun run check` refuses anything else.

## Rules
- No prototypes, scaffolds or placeholders: add a folder only with a working, tested unit.
- Follow the tree in `docs/architecture.md`: programs in `apps/`, Bun packages in
  `packages/`, Rust in `crates/`, C and assembly in `corelib/`, upstreams as submodules in `third_party/`.
- Assemble upstream first; never copy an upstream's code or directory layout into the tree.
- Nothing hardcoded: names, hosts and domains come from `ay.toml`; versions are read live.
- Run the repository's own checks before every push (`bun run check`, plus `cargo` checks for `crates/`).
- Heavy builds run on the `build` host, tests on `test`, production only on `prod` (`ay.toml` [hosts]).
- Repositories are sibling checkouts under one root, the stack is ordered 1 `fw`, 2 `aphrody`, 3 `ay`, 4 `nie`, 5 `shenron`, then satellites, and a Rust dependency between repositories may only point down the stack (to `fw` from everyone, as `../fw/crates/fw-*` through `[workspace.dependencies]`), never up and never in a cycle.
- Work on `main`; no branches, worktrees, stash or reset. No AI attribution in commits.
- One checkout per repository on each host, one monorepo, one submodule registry: never clone, copy or `git worktree add` a tree to build,
  test or verify; fast-forward the existing checkout and run the gate there.
- Proof is an inspected screenshot, a checked API response or a real UI test, never an HTTP status.
- Secrets are never printed or committed; the repository is public.
- No data about the owner's machine, the fleet or the state of the work in tracked files or agent files: hosts, host paths and local
  checkout hints live in the git-ignored `ay.local.toml` (shape in `ay.local.example.toml`); everything generated (reports, inventories,
  telemetry, research notes, the work ledger, the plan page, learning digests) goes to the git-ignored `.private/` (`tools/local.ts`).
  Docs name hosts by role (`<build-host>`, `<test-host>`, `<prod-host>`). `bun tools/private-gate.ts` enforces it.

## Cloud units (packages/cf-control-plane, apps/cf-gateway, apps/tools-release, python/, cpp/)
- Account, zone and tunnel ids, public host addresses and e-mail addresses live only in the git-ignored `cf.local.toml` (shape in
  `packages/cf-control-plane/cf.local.example.toml`, generated by `bun tools/cf-bootstrap-local.ts`); `tools/private-gate.ts` reads its values.
- Prefer ecosystem libraries over wrappers: TypeScript Workers use the official `cloudflare` SDK, `hono`, `zod`, `wrangler` and the patched
  `jsonc-parser` (`patches/`); C++23 uses Bazel with `rules_cc`, Abseil and GoogleTest on Clang/LLVM; Python 3.13 uses the official
  `cloudflare` SDK, `pydantic` v2 and `httpx` through `uv`, checked with `ruff`.
- Run `wrangler types` after changing the bindings of a Worker; every routed production Worker sets `limits.cpu_ms`, sampled
  `observability` logs and traces, and `workers_dev = false`.
- Checks: `just cf-audit`, `just py-check`, `just cpp-check` (Bazel runs on the build host).
- Official Cloudflare skills belong to the Cloudflare plugin and are never copied here; `apps/cf-gateway` serves only their discovery
  index (`bun tools/cf-skills-index.ts`).
